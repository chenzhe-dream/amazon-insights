# 电商商品图片视觉分析

## Purpose

本 Skill 用于分析 Amazon 及其他电商平台的商品主图、辅图和其他 Listing 视觉素材。

核心目标不是简单描述“图片里面有什么”，而是理解：

- 这张图片主要在讲什么
- 卖家使用什么视觉方式表达
- 图片重点突出什么商品信息或卖点
- 消费者通过图片能够获得哪些有效信息
- 这张图片在整个 Listing 图片体系中承担什么作用

输出结果主要用于：

- Amazon 竞品图片横向分析
- Listing 主辅图拆解
- 图片卖点覆盖分析
- 图片类型统计
- 场景覆盖统计
- 图片顺序研究
- 视觉表达策略研究
- 自有 Listing 图片规划
- 批量商品图片数据库标注

适用于包括但不限于：

玩具、儿童用品、户外运动、灯具照明、家居用品、家具、园艺用品、工具、收纳用品、宠物用品、厨房用品及其他消费品类。

---

# When to Use This Skill

当用户提出以下类型任务时，优先调用本 Skill：

- 分析 Amazon 主图或辅图
- 分析竞品 Listing 图片
- 给每张辅图生成备注
- 提炼图片卖点
- 判断图片在讲什么
- 判断图片类型
- 提炼场景图表达的信息
- 分析图片中的文字、参数、尺寸或功能
- 对多张商品图片进行批量结构化分析
- 为竞品横向对比系统生成图片标签
- 对 ASIN 图片进行视觉策略拆解
- 分析竞品第1张、第2张、第3张等图片分别在表达什么
- 给图片生成结构化 JSON
- 为商品图片建立可检索、可统计的数据字段

如果用户只是要求 OCR 全量识别文字，而不需要理解图片营销表达目的，本 Skill 可以辅助，但不应将“营销分析”强加给用户。

---

# Core Principle

始终围绕以下问题进行分析：

> 为什么卖家要把这张图片放在 Listing 中？

而不是只回答：

> 这张图片里面有哪些物体？

分析重点必须是：

**视觉表达方式 + 商品信息 + 消费者理解 + Listing 图片作用**

---

# Inputs

## Required Input

至少提供：

- 一张商品图片

或：

- 多张商品图片

## Optional Context

用户可能同时提供：

- ASIN
- 品牌
- 商品名称
- 商品类目
- 图片序号
- 主图/辅图标记
- Amazon 站点
- 商品参数
- Listing 标题
- Bullet Points
- 已知商品卖点
- 竞品品牌
- 其他背景信息

这些信息只能作为辅助上下文。

## Evidence Priority

关于“当前图片究竟表达什么”的判断，证据优先级为：

1. 当前图片中清晰可见的内容
2. 当前图片中清晰可识别的文字
3. 当前图片中的参数、箭头、图示、局部放大等视觉证据
4. 用户明确提供并能够与图片对应的商品信息
5. 商品类目常识

不得因为类目常识或商品名称，擅自把图片中没有体现的信息认定为当前图片的卖点。

# Analysis Workflow

处理每一张图片时，按照以下顺序执行。

## Step 1 — Understand the Image

首先观察当前图片整体内容，识别：

- 产品是什么
- 产品处于什么状态
- 是否存在人物
- 人物正在做什么
- 是否存在实际使用场景
- 是否存在局部结构放大
- 是否存在箭头或功能示意
- 是否存在尺寸线
- 是否存在数字或参数
- 是否存在配件
- 是否存在多个颜色或款式
- 是否存在产品之间的对比
- 是否存在使用前后对比
- 是否存在文字标题或说明
- 是否存在安装、折叠、调节、操作过程
- 是否存在灯光、喷水、运动等实际使用效果

不要立即生成备注。

先理解画面想表达什么。

---

## Step 2 — Determine the Communication Objective

判断：

> 这张图片最主要希望消费者理解什么？

可能是：

- 一个核心功能
- 一个产品结构
- 一个产品细节
- 一个尺寸信息
- 一个性能参数
- 一个使用场景
- 一个适用环境
- 一种使用方法
- 一种安装方式
- 一种调节方式
- 一个实际使用效果
- 一组配件
- 一个容量或空间
- 多个颜色或款式
- 产品与其他方案之间的差异
- 品牌或生活方式表达

一张图片可能同时包含多个信息。

只优先提炼最重要的 1–3 个。

---

## Step 3 — Determine Image Types

从以下类型中选择最符合当前图片的 1–3 个：

- 产品展示
- 核心卖点
- 功能展示
- 产品细节
- 结构展示
- 材质/工艺
- 尺寸参数
- 性能参数
- 使用场景
- 使用效果
- 人群展示
- 使用方法
- 操作说明
- 安装说明
- 调节方式
- 折叠/收纳
- 清洁维护
- 产品对比
- 使用前后对比
- 多颜色/多款式
- 配件展示
- 套装内容
- 包装展示
- 兼容性/适配性
- 空间容量
- 灯光/视觉效果
- 安全提示
- 注意事项
- 品牌形象
- 生活方式
- 其他

如果没有完全匹配的类型，可以创建一个简短、准确的新类型。

不得为了填满字段而强行选择多个类型。

---

# Important Distinction

必须区分：

## Image Type / Visual Method

指卖家“用什么方式讲”。

例如：

- 使用场景
- 产品细节
- 参数图
- 尺寸图
- 对比图
- 结构图

## Selling Point / Information

指卖家“具体在讲什么”。

例如：

- 发光轮
- 高度调节
- 折叠收纳
- 多档亮度
- 大容量
- 可旋转灯头
- 多层储物
- 可调节喷头

例如：

图片类型：

`使用场景`

核心卖点：

`发光轮`

和：

图片类型：

`产品细节`

核心卖点：

`发光轮`

属于两种不同的视觉策略。

不得混为一谈。

# Visual Analysis Dimensions

根据实际图片选择相关维度分析。

图片没有体现的内容不要强行填写。

## Product

可识别：

- 产品外观
- 产品形态
- 产品颜色
- 产品款式
- 产品数量
- 产品组合关系
- 展开状态
- 折叠状态
- 使用状态
- 不同角度

---

## Functions

仅识别图片明确体现的功能，例如：

- 调节
- 升降
- 折叠
- 旋转
- 移动
- 照明
- 发光
- 喷水
- 储物
- 收纳
- 倾斜
- 滑动
- 开合
- 拼接
- 拆卸
- 模式切换
- 安装
- 锁定
- 伸缩

不得因为某类产品通常拥有某功能，就自行添加。

---

## Structure

识别图片重点展示的结构，例如：

- 轮子
- 支架
- 扶手
- 桌腿
- 抽屉
- 柜门
- 层板
- 灯头
- 灯杆
- 底座
- 接口
- 开关
- 喷头
- 管道
- 铰链
- 插头
- 卡扣
- 把手
- 电池仓
- 连接件

不要仅说明存在某个结构。

进一步判断：

> 为什么卖家要特意展示这个结构？

---

## Parameters

只提取图片明确出现且能够确认的参数，例如：

- 长度
- 宽度
- 高度
- 直径
- 重量
- 容量
- 数量
- 档位
- 角度
- 功率
- 流明
- 色温
- 距离
- 速度
- 套装数量
- 规格

重要数字应尽量准确保留。

无法确认数字时不要猜测。

---

## Scene

识别实际可见的使用环境，例如：

- 客厅
- 卧室
- 厨房
- 餐厅
- 办公室
- 儿童房
- 浴室
- 车库
- 花园
- 庭院
- 草坪
- 公园
- 道路
- 露营
- 沙滩
- 户外运动环境
- 家庭娱乐环境
- 儿童活动环境

不要把单纯的背景装饰过度解释为商品功能。

---

## People

可识别：

- 成人
- 儿童
- 家庭
- 单人
- 多人

重点识别人物正在如何使用产品，例如：

- 骑行
- 坐
- 躺
- 阅读
- 玩耍
- 安装
- 操作
- 收纳
- 浇水
- 搬运
- 清洁
- 运动

除非图片明确标注，不要自行判断人物具体年龄。

---

## Effects

识别图片明确展示的实际视觉效果，例如：

- 发光效果
- 照明效果
- 喷水效果
- 收纳效果
- 装饰效果
- 展开效果
- 折叠效果
- 不同模式
- 运动状态
- 工作状态
- 使用前后状态

必须区分：

> 图片视觉展示了什么

与：

> 产品实际性能能够达到什么

不得通过一张视觉效果图推导没有证据支持的性能结论。

---

## Comparison

识别是否存在：

- 不同型号对比
- 不同尺寸对比
- 不同颜色对比
- 不同状态对比
- 不同档位对比
- 不同角度对比
- 使用前后对比
- 本产品与其他方案对比
- 新旧版本对比
- 不同配件组合对比

存在对比时，需要总结：

- 比较对象是什么
- 比较维度是什么
- 图片希望突出什么差异

# Text Analysis Rules

如果图片中存在文字，执行以下规则。

## Do

优先提取：

- 主标题
- 功能名称
- 重要卖点
- 数字
- 尺寸
- 数量
- 档位
- 参数
- 使用方式
- 重要提示

英文或其他语言文案可以概括成简洁中文。

重要数字尽量保留原始信息。

## Do Not

不要：

- 对全部文字逐字 OCR
- 把 Logo 当成核心信息
- 把装饰性小字当成卖点
- 重复输出标题和画面已经表达的相同信息
- 猜测看不清的文字

如果部分文字无法辨认：

使用：

`部分文字无法确认`

不要自行补全。

---

# Text + Visual Integration

图片文字和视觉画面必须综合理解。

例如：

图片文字：

`4 Adjustable Heights`

图片画面：

同时展示产品四种不同高度。

正确理解：

`展示4档高度调节功能，并通过不同高度状态表现产品的可调节设计。`

不要只返回：

`4 Adjustable Heights`

也不要只返回：

`有4辆不同高度的产品。`

---

# Category-Neutral Rules

本 Skill 必须保持跨类目通用性。

不得针对单一类目预设卖点。

例如：

玩具不默认：

- 安全
- 适龄
- 无毒

灯具不默认：

- 防水
- 节能
- 高亮
- 长寿命

家具不默认：

- 高承重
- 人体工学
- 稳固
- 耐用

园艺产品不默认：

- 防晒
- 耐候
- 超大覆盖范围

户外运动产品不默认：

- 防水
- 抗风
- 高强度
- 安全防护

只有图片明确存在证据时才允许提取这些信息。

---

# Hallucination Guardrails

严禁编造图片中不存在的信息。

除非存在明确视觉或文字证据，否则不得自行认定：

- 产品安全性
- 防水等级
- 防火能力
- 无毒
- 环保
- 认证
- 材质
- 承重
- 使用寿命
- 具体适用年龄
- 功率
- 流明
- 色温
- 耐候性
- 抗风能力
- 人体工学
- 防滑能力
- 稳定性
- 耐用性
- 医疗作用
- 健康作用
- 专业等级
- 性能优于竞争产品

---

# Conservative Language

对于只能观察但无法完全确认的信息，使用客观、保守表达。

推荐：

`展示户外庭院使用场景。`

不要：

`适用于所有恶劣天气。`

推荐：

`展示产品展开后的内部空间。`

不要：

`可舒适容纳5名成年人。`

除非图片有明确证据。

推荐：

`画面突出底部结构。`

不要：

`底部结构更加稳定安全。`

除非存在相应文字或证据。

---

# Remark Generation

`remark` 是本 Skill 最重要的最终字段。

它必须回答：

> 这张图片主要向消费者传达什么？

优先采用：

**展示方式 + 核心信息 / 卖点**

例如：

`尺寸标注图，展示桌面宽度、高度及整体占地尺寸。`

`儿童户外骑行场景，突出产品实际骑行状态及目标使用场景。`

`夜间庭院亮灯效果，重点展示灯具点亮后的照明及装饰视觉表现。`

`抽屉及内部空间展示，突出家具的分区储物方式。`

`喷水状态实拍，展示园艺喷头工作时的实际出水效果。`

`局部结构放大，展示接头连接位置及安装连接方式。`

---

# Remark Style Rules

remark 必须：

- 信息密度高
- 简洁
- 客观
- 方便运营人员快速浏览
- 适合竞品横向比较
- 描述图片的营销表达目的
- 避免广告化语言

建议长度：

20–80 个中文字符。

信息复杂时允许两句话。

原则上不超过 120 个中文字符。

不要固定使用：

`这张图片展示了……`

作为每条备注开头。

# Bad vs Good Examples

## Example 1 — Toy / Scooter

Bad:

`一个小孩正在骑滑板车。`

Good:

`儿童户外骑行场景，突出产品实际骑行状态及儿童娱乐使用环境。`

---

## Example 2 — Outdoor / Tent

Visual:

帐篷展开，并标注长宽高。

Good:

`尺寸参数图，展示帐篷展开后的长宽高及整体空间尺寸。`

---

## Example 3 — Lighting

Visual:

灯具在夜间庭院点亮。

Good:

`夜间庭院使用场景，重点展示灯具点亮后的照明及装饰视觉效果。`

---

## Example 4 — Home Storage

Visual:

收纳产品打开后存在多个分区。

Good:

`内部结构展示，通过多个分区表现产品的分类收纳方式。`

---

## Example 5 — Furniture

Visual:

真人坐在沙发上。

Good:

`真人坐姿使用场景，通过人物比例展示沙发实际使用状态及座位空间表现。`

---

## Example 6 — Gardening

Visual:

喷头正在草坪喷水。

Good:

`户外浇灌场景，展示喷头工作状态及实际喷水视觉效果。`

# Confidence

每张图片必须判断分析置信度。

仅允许：

`high`

`medium`

`low`

## high

适用于：

- 图片清晰
- 主要文案清晰
- 产品状态明确
- 核心表达可以明确判断

## medium

适用于：

- 主要画面能够识别
- 主要表达能够判断
- 但部分文字、数字或细节无法确认

## low

适用于：

- 图片模糊
- 分辨率过低
- 文字过小
- 核心信息存在明显不确定性
- 只能有限判断

不得为了生成完整结果而人为提高 confidence。
