## 代码路径和根因候选

1. `overview-complete-windows.ts` 以每条事实及其关联缺口为原子组，然后贪心拼接，直到结构约束或计量拒绝；并非预设每窗口两条事实。
2. `market-overview-windows-step.ts` 仅接受能生成恰好一个batch的窗口；`market-semantic-batch-preparation.ts` 后续每batch创建一个model-batch。所以73准备窗口对应预计73解释调用，不能理解为一个模型请求的73行。
3. **已确认的保守计量机制**：`market-request-admission.ts:26` 用完整请求 JSON 的 UTF-8 字节数 +512 作为输入token上界，包含指令、序列化输入、响应schema和协议包。`market-semantic-batch-meter.ts:38` 再预留256。
4. `market-model-runtime.ts:73` 将overview的estimatedInputTokens直接设为任务maxInputTokens；任务目录为12000。因此本任务有效允许的完整请求JSON约为 **11232字节**（12000-512-256），不是模型真实tokenizer测量的12000 tokens。长schema、中文指令、证据依赖闭包与重复范围限制共同消耗此预算，**很可能是每2条分布事实就切窗的主要放大因素**。
5. 仍有独立结构约束：每请求128个metrics、32个facts/gaps、20个维度及各维引用限制等。没有对每次 rejected candidate 保存“结构拒绝还是计量拒绝”的诊断，因此不能仅凭窗口清单断言每次拆分都由字节预算触发。
6. 每窗口补充事实相关的分母/分子依赖及限制说明，保证证据完整，但会重复固定上下文。调整应以真实请求计量和业务维度组织共同验证，不能直接删限制或放大预算来伪造通过。
