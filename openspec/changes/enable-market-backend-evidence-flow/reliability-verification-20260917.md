日期：2026-09-17。工作区：`integrate-xydc-variant-20260905`。按本 change 的 reliability-implementation-plan-20260917.md 实施，前端未改动，正式服务未发布或重启。

## 本次实现

1. **MCP 会话复用**：SellerSprite 市场任务使用连接器持有的会话池，按组织、任务、凭据指纹、端点及协议隔离。最多 32 个会话，空闲 30 秒释放，同会话串行执行 RPC；断线淘汰、取消和服务关闭均释放连接。非市场调用保持原路径。每个真实 HTTP 请求仍进入现有资源计量。
2. **本地准入等待**：TS 与脚本 governor 透传封闭原因及数据库时钟计算的 retryAt。来源步骤将本地窗口/并发等待持久化，不消耗普通失败重试次数；保留全部等待审计和已完成兄弟步骤。人工暂停不虚构恢复时间。取消、租约和组织隔离保持有效。
3. **引文校验**：错误包含具体字段路径及封闭原因。仅对当前形态模型结果，在同一 ASIN 的原引用字段内唯一精确匹配原 quote 时修正坐标；不模糊匹配、不跨字段/商品、不把协议错误变成“未知”。保存原/新坐标与版本，审计路径遵循最终 ASIN 顺序，旧结果读取继续严格验证。
4. **模型诊断与超时**：新增市场专用 `AGENT_MARKET_SHAPE_TIMEOUT_MS` / `AGENT_MARKET_THEME_TIMEOUT_MS`，允许整数 1000–120000ms；未配置仍保持原 60000ms 上限及更低的基础设置。有效超时进入配置身份，批次/阶段截止和金额/token 预算不变。记录请求发出、响应头、响应体结束/失败/取消、耗时和安全中止分类；不记录密钥、原始载荷、URL 或异常文本。DNS/TCP/TLS 无法由 fetch 观测，保留 null，不推断上游排队原因。
5. **验收驱动**：一次 tick 返回 false 不再结束测试；按持久化 nextAttemptAt 等待，识别已无待处理步骤的 partial、失败、取消及验收截止。真实测试继续使用正常任务、预算、审计和读取链路。

## 第二轮测试补充：物理请求计数的原因已查明

用户要求继续本地真实模型验证后，增加了仅用于验收的 fetch 分阶段计数。本轮总览复现：13 次工具查询对应 16 次初始 HTTP 请求（1 initialize、1 initialized、1 GET、13 tools/call），随后又产生 14 条迟到的 notifications/cancelled，合计 30 次。这里的额外 14 次不能笼统解释为正常供应商协议开销。

已完成请求的 `AbortSignal.timeout` 到期后，当前 SDK 注册的 abort listener 仍调用 cancel；同一个首轮信号覆盖初始化和工具请求，产生两条通知，后续每次成功工具请求又各产生一条。仅本地假服务器也能复现：35ms 已返回成功，300ms 截止后出现两条取消通知，实际业务只派发一次。

记录在任务 8.6；本轮测试期间未修改生产实现或关闭请求计量。第二轮完整验收记录另附，不能把上一轮的连接池实现/回归通过视为不存在此缺陷。
