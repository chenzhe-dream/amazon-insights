## Why
人员读取与模块配置保存偶发 504，当前代理只等待 10 秒；保存响应超时无法证明事务失败。最初观察到日志文件元数据为零；后续直接读取获得了请求记录，仍缺少可区分响应阶段的诊断。用户批准修复并指定等待 60 秒。

## What Changes
- 人员、使用统计、模块配置及前置会话读取的代理等待上限改为 60 秒。
- 个人/批量模块保存遇到响应超时或网络中断后，只读核对当前配置；无法核实时明确表示结果待确认，不自动重放写请求。
- 核实正式日志可读取，保留现有启动方式；记录晚于提交的响应断开和耗时。
- 管理链路输出脱敏的请求关联及分段耗时，保留鉴权边界。

## Capabilities
### New Capabilities
- `admin-request-reliability`: 管理页等待、结果核对与日志诊断。

## Impact
Web 代理、模块配置保存交互、后端路由与定向测试。无数据库迁移，不调整分析算法、其他任务超时或访问权限。历史 504 的根因仍待新日志验证。
