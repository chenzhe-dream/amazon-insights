## Purpose

为单一内网部署提供不泄露会话秘密的管理员用户活动看板，并以现有可撤销会话记录给出可验证、可解释的近期活动与会话状态。

## ADDED Requirements

### Requirement: 管理员用户看板必须 fail-closed
系统 SHALL 提供独立的 `/admin/users` 页面和 `GET /v1/admin/users` 接口，并且只允许当前已认证、状态有效且角色为 `admin` 的用户读取看板数据。

#### Scenario: 管理员访问用户看板
- **WHEN** 已认证且账号有效的 admin 打开 `/admin/users`
- **THEN** 页面在确认 admin 身份后读取并展示用户活动数据

#### Scenario: 普通用户访问用户看板接口
- **WHEN** 已认证 member 请求 `GET /v1/admin/users`
- **THEN** 系统返回 403 且不返回任何用户或会话数据

#### Scenario: 未认证访问用户看板接口
- **WHEN** 未认证请求访问 `GET /v1/admin/users`
- **THEN** 系统返回 401 且不泄露用户是否存在

#### Scenario: 非管理员直达用户看板页面
- **WHEN** 未认证用户或 member 直接打开 `/admin/users`
- **THEN** 页面在身份门禁通过前不得请求管理员数据，member 身份确认后仍不得发起该读取请求或渲染用户数据

### Requirement: 可见的已认证页面必须发送有界活动心跳
系统 SHALL 让当前可见且已认证的页面向 `POST /v1/auth/activity` 发送空负载活动心跳；进入该状态时立即发送一次，此后保持可见期间每 60 秒最多发起一次，并在页面隐藏、身份失效或组件卸载时停止。

#### Scenario: 已认证页面开始可见
- **WHEN** admin 或 member 的已认证页面进入可见状态
- **THEN** 客户端立即发送一次活动心跳，并在持续可见时按 60 秒周期续报

#### Scenario: 页面隐藏后暂停心跳
- **WHEN** 已认证页面从可见变为隐藏
- **THEN** 客户端停止周期心跳，直到页面再次可见

#### Scenario: 页面恢复可见
- **WHEN** 已认证页面从隐藏恢复为可见
- **THEN** 客户端立即尝试一次心跳并重新开始 60 秒周期，服务端仍执行写入节流

#### Scenario: 身份失效或页面卸载
- **WHEN** 当前会话变为未认证、认证身份切换或页面组件卸载
- **THEN** 客户端取消后续心跳且不得把旧身份的心跳延续到新身份

### Requirement: 活动写入必须使用服务端时钟并保持幂等
系统 MUST 只更新当前认证 principal 对应的仍有效会话，使用服务端时间写入该会话的最后活动时间，并对同一会话执行至少 60 秒的原子写入节流。请求不得接受客户端用户标识、会话标识或活动时间。

#### Scenario: 首次有效活动
- **WHEN** 有效会话的 `last_seen_at` 为空并收到活动心跳
- **THEN** 系统把服务端当前时间写入该会话并返回成功

#### Scenario: 节流窗口内重复活动
- **WHEN** 同一有效会话在最近一次写入后的 60 秒内收到一个或多个并发心跳
- **THEN** 系统返回幂等成功且不再次推进持久化活动时间

#### Scenario: 节流边界到达
- **WHEN** 同一有效会话的最后活动时间早于或等于服务端当前时间减 60 秒
- **THEN** 恰有一个并发请求可把最后活动推进到本次服务端时间，其余请求为幂等成功

#### Scenario: 会话已撤销或过期
- **WHEN** 心跳对应会话在认证与条件更新之间已撤销或已到期
- **THEN** 系统不得更新任何会话并以未认证结果 fail-closed

### Requirement: 用户摘要必须从现有用户和会话记录确定性聚合
系统 SHALL 以一次服务端 `asOf` 时间为基准列出当前部署组织内的全部账号，并为每个账号返回账号、显示名、角色、账号状态、登录次数、最后登录时间、最后活动时间和有效会话到期时间。登录次数等于该账号的全部会话记录数；最后登录时间是最大的会话创建时间；最后活动时间是全部非空 `last_seen_at` 的最大值；有效会话到期时间是全部当前有效会话到期时间的最大值，无对应值时返回 `null`。

#### Scenario: 用户从未登录
- **WHEN** 一个账号没有任何会话记录
- **THEN** 登录次数为 0，最后登录、最后活动和有效会话到期时间均为 `null`

#### Scenario: 用户有多个会话
- **WHEN** 一个账号有多个历史与当前会话
- **THEN** 系统基于全部会话计算计数和最大时间，但只把未撤销、未过期且账号有效的会话计入有效会话到期时间

#### Scenario: SQLite 与 PostgreSQL 读取相同逻辑数据
- **WHEN** 两种受支持数据库包含等价的用户、会话和 `asOf` 输入
- **THEN** 两种实现返回相同的摘要值、最近登录记录和展示状态

### Requirement: 在线态必须使用固定优先级和五分钟证据窗
系统 SHALL 按 `账号已禁用`、`近期在线`、`会话有效但近期无活动`、`未登录`、`会话已失效` 的顺序选择唯一展示状态。`近期在线` 只在账号有效、至少一个会话未撤销且未过期，并且该有效会话存在位于闭区间 `[asOf - 5 分钟, asOf]` 的 `last_seen_at` 时成立。

#### Scenario: 禁用状态优先
- **WHEN** `user.status=disabled` 且历史会话仍包含近期活动或未来到期时间
- **THEN** 展示状态仍为 `账号已禁用`，且不存在有效会话到期时间

#### Scenario: 恰好位于五分钟边界
- **WHEN** 有效会话的最后活动时间恰好等于 `asOf - 5 分钟`
- **THEN** 展示状态为 `近期在线`

#### Scenario: 超过五分钟边界
- **WHEN** 账号有有效会话但所有有效会话的最后活动均为空或早于 `asOf - 5 分钟`
- **THEN** 展示状态为 `会话有效但近期无活动`

#### Scenario: 有历史但没有有效会话
- **WHEN** 账号有效、至少登录过一次，但所有会话均已撤销或在 `asOf` 时已到期
- **THEN** 展示状态为 `会话已失效`

#### Scenario: 撤销会话的近期活动不构成在线证据
- **WHEN** 最近五分钟内的最后活动只属于已撤销会话
- **THEN** 该活动不得使账号显示为 `近期在线`

### Requirement: 最近登录记录必须有界且可解释
系统 SHALL 为每个账号返回按登录时间倒序排列的最近 10 条登录记录，每条只包含登录时间、最后活动时间、到期时间和失效原因。失效原因 SHALL 按账号禁用、会话撤销、会话到期的优先顺序派生；仍有效时为 `null`。

#### Scenario: 登录记录超过十条
- **WHEN** 一个账号存在超过 10 条会话记录
- **THEN** 摘要保留全部记录的登录次数，但展开区只返回最新 10 条

#### Scenario: 会话已撤销
- **WHEN** 最近登录记录的 `revoked_at` 非空且账号未禁用
- **THEN** 该记录的失效原因为 `revoked`

#### Scenario: 会话自然到期
- **WHEN** 最近登录记录未撤销但到期时间早于或等于 `asOf`
- **THEN** 该记录的失效原因为 `expired`

#### Scenario: 账号已禁用
- **WHEN** 最近登录记录所属账号已禁用
- **THEN** 该记录的失效原因为 `account-disabled`，不将它描述为有效会话

### Requirement: 管理员响应不得泄露敏感认证材料
系统 MUST 使用严格响应合同，并且接口、页面与可展开记录均不得包含 Cookie、原始 token、token hash、密码 hash、session id、IP、凭据或可用于重放会话的派生值。

#### Scenario: 管理员读取用户状态
- **WHEN** admin 成功请求 `GET /v1/admin/users`
- **THEN** 响应只包含已声明的用户摘要、派生状态、界定时间和最近登录字段

#### Scenario: 底层记录含有敏感列
- **WHEN** 数据库会话行包含 session id 与 token hash
- **THEN** repository 边界之后的公开合同和序列化响应均不携带这些字段

#### Scenario: 数据读取或合同校验失败
- **WHEN** 用户状态聚合无法完成或产生不符合严格合同的数据
- **THEN** 系统返回安全错误且不返回部分用户数据、底层查询细节或敏感值
