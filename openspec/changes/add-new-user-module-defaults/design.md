## Context
当前支持按钉钉人员配置模块。未配置人员沿用全部模块，枚举和界面数量存在硬编码。

## Goals / Non-Goals
目标：新用户默认配置、注册表同步、并发版本控制、组织隔离与可审计。
非目标：改变已有用户、重构业务权限、变更市场分析、发布服务；SQLite 无模块可见性存储，本次沿用正式 PostgreSQL 实现边界。

## Decisions
1. MODULES 是父模块清单的唯一来源，schema、总数与两个配置界面从中生成。子页面继续继承父模块并由 TabId 映射约束。新增父模块须在注册表登记；登记不等于默认开放。
2. 新增组织级 module_visibility_defaults 表。未配置时使用冻结的初始九模块基线，兼容当前行为；未来新模块不加入该基线，已有保存数组也不扩张。原有用户没有记录时继续沿用原有显示范围。
3. 钉钉新用户创建与可见性快照在同一事务提交。默认配置保存和快照读取共享组织级事务锁，以提交顺序确定生效边界。返回用户重登不重新套用；本地账号、初始化管理员和通用创建入口保持现状，不初始化该默认快照。
4. user_module_visibility 增加 configuration_source，默认 personal 兼容历史；新建快照标记 new-user-default，同时保存默认版本。个人修改变为 personal。
5. 默认设置使用现有管理资格鉴权、组织隔离、乐观版本和审计。系统所有者始终可见全部模块。勾选用户统计不授予其专有访问权限。
6. 按用户实施中补充要求，本地账号除保留的管理账号外后续停用，本次不处理其去留、不扩大人员列表。现有人员管理继续限定组织内活跃钉钉账号；本地管理账号原有可见性与资格保持不变。
7. 管理页面增加新用户默认模块抽屉，注明仅适用于随后新建账号、允许清空、读取失败禁止保存、冲突不覆盖、取消不写入。共用样式与模块注册表。

## Risks / Trade-offs
首次上线前已存在的用户不自动补写快照，避免意外降权。新增父模块必须同时接入导航映射和既有业务授权；本功能只自动同步注册后的配置选项。
数据库迁移仅新增表与列，旧个人配置保留；上线需按既有部署流程执行迁移。

## Migration Plan
先运行 0054 迁移，再更新服务和前端。无需数据回填。当前阶段仅隔离数据库验证。

## Open Questions
无。用户已确认新增模块自动加入列表，管理员决定默认开放；本地账号保持现状，只对钉钉新用户应用默认策略。
