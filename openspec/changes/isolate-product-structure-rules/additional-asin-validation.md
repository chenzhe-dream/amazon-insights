- 17/36 保存记录的总结明确标注模拟或合成测试，其余也未在本轮外部认证。统一称“保存输入回放”，不能称全部真实消费者验证。B08B4GH4QL 关键词快照为空，不补造数据。

## 1. 混合汇总丢失需求归属（优先修复）

组合：三轮滑板车 `B0BPXRVWYK` + 融蜡灯 `B0CTJGJL2T`。

滑板车原文存在“希望从根本上解决后轮融化问题”；蜡灯原始记录没有任何“后轮”内容。蜡灯单独运行没有后轮功能项；混合运行后，最终产品定义的差异化及可选功能中出现“从根本上解决后轮融化问题”，同时为蜡灯生成 `supported` 决策：

- `final-dimension:功能分层-differentiation-1:B0CTJGJL2T`
- `final-dimension:功能分层-optional-3:B0CTJGJL2T`

另有 `final-dimension:功能分层-notInV1-1:B0CTJGJL2T` 将“后轮故障”解释为蜡灯支持项。

代码路径：`buildFeatureLayers` 从合并主题生成无 ASIN 归属的文字；`explainFinalActions` 将未标注归属的候选重新分配给每个上下文。`textActionConditions` 漏掉中文“后轮/前轮”，`needSupportsCandidate` 在条件为空时允许任意可用需求满足判断。故引用 ID 属于蜡灯，并不证明该需求来自蜡灯；解释面板也会错误显示规则通过。

修复要求：候选从生成、汇总到解释必须保留原始 ASIN 与具体需求引用；未识别结构条件不能等同于需求相关性成立。补前后轮词形仅作为回归补充，不能替代来源隔离。

## 2. “控制”多义词套错开发动作

- `B0CTJGJL2T`：“希望实现亮度和温度分离控制，使低亮度下仍能保持较强加热。”
- `B0DPG6SNV1`：“希望提高短期故障控制，减少使用一天或一周后停止工作的情况。”

两者均被生成“按实际握持位置比较握持舒适度、操作力度及连接牢固性，核对适龄条件”，并因缺少握持证据变成 `needs_check`。来源需求仍在，但动作和待核对原因已偏离原意。

代码路径：`groundedAction` 以宽泛的“控制”触发握持动作模板。修复要求：区分温控、电控、质量控制与手部操控；不确定时保留原问题及针对它的验证方向，不注入握持或适龄条件。

## 3. 融蜡灯正常调光需求被阅读用途拦截

`B0DZFGTCLR` 原文：“希望支持无级调光或提供更多亮度档位。”

生成动作被追加“照明均匀性、眩光”等模板内容，再被要求具备 `reading_illumination`。该 ASIN 有融蜡用途，阅读用途前提不成立，`supply:unmet:2` 和 `voc-unmet:2` 均变成 `rejected / structure_incompatible`。

修复要求：把亮度调节、融蜡加热控制与阅读用途分开；不能由动作模板添加的新文字制造不存在的前提。是否可执行改进仍应核对实际电路、光源和需求，不必先证明它是阅读灯。

反例边界：`B0GWDV1FL5` 同 ASIN 原文明确存在“可作为阅读灯使用”，其阅读属性有来源，不能仅凭蜡灯类目将其删除。产品用途允许多种，判断须保留证据。
