## Goals / Non-Goals

**Goals:** 流程节点与规则、来源、输出一一对应；所有受影响消费链路共用结构判定；运营能阅读实际规则并解释具体结果；未知类目仍有有效输出。

**Non-Goals:** 不搭建通用推理平台、全类目模板库、规则编辑后台或新采集服务；不改变无关模块与评分体系。解释的是可审计的条件和来源，不是模型内部推理过程。

## Decisions

### 1. 使用产品结构信息，不扩充单一产品族枚举来承担全部判断

为每个组织/项目/站点/ASIN 建立 ProductContext：原名、别名、用途、形态、结构属性与来源引用。属性携带 supported/absent/unknown，conflicts 单独存放。来源保存原文位置、类型、可用时间、否定及限定语；无时间不编造。类目和标题提供上下文，明确的结构描述才参与相应结构判断；来源冲突不以固定多数票掩盖。

保留旧 productFamily 兼容字段供无关消费者使用，但它不再作为受影响结构动作的唯一依据。逐个识别后再汇总；不通过全组标题拼接给单个产品赋形态。

替代方案：仅排除 Snow Scooter 无法覆盖低幼关键词路径；不断增加类目分支会重复出现 lamp 等词误判，因此选用跨类目的属性条件。

### 2. 将事实、需求和建议分开，并逐条判定

需求可以来自项目级关键词，但不能成为 ASIN 的硬件事实。候选输出携带 kind=fact/proposal、适用 ASIN、需求依据、结构前置条件和内容。执行结果为 supported/rejected/needs_check；不同输出类型分别评估，不将“竞品未配置”误当成“新方案不可建议”。

规则条件明确区分必要、禁止、未知及冲突。例如轮距动作需要轮式形态；“三轮已存在”必须有轮数事实；“改成三轮”是新方案，需要痛点和适用性依据，不能由 toddler 自动生成。未知类目基于已有属性和 VOC 生成动作；涉及尚不明确的硬件才单独核对。禁止用无来源的固定尺寸、年龄或标准填补空白。

替代方案：只过滤最终字符串无法给出真实原因，也易漏掉模板变体；本方案在候选生成和决策边界接入，不靠页面删词。

### 3. 共享、版本化的规则定义及执行记录

设计 RuleDefinition 包含 id、version、flowNode、中文名称/目的、前置条件、排除条件、缺失/冲突策略、正反例。条件使用受支持的可执行谓词，展示从同一条件数据生成；不采用任意脚本执行或运营编辑。新谓词必须同时实现执行和中文展示，并通过一致性契约测试。

DecisionRecord 包含 ruleSetVersion、ruleIds/versions、inputScope、candidateId、kind、ASIN、matchedConditions、evidenceRefs、outcome、reasonCode、中文摘要和核对事项。应用层及服务端消费同一纯规则模块；UI 不二次判定。解释仅保存与该决策相关的最小数据，不复制全量原始采集记录。

新增模块要消费同一规则及记录契约，不得自行写类目到硬件映射。算法规则变化必须更新版本、示例、规范场景和回归用例。

### 4. 运营只读查看作为本变更交付的一部分

采用现有页面风格和组件，默认规划入口为相关分析区标题旁的“分析规则说明”；无结果也能打开。以抽屉或详情面板展示：
- 概览：中文原则、流程图、规则版本。
- 规则列表：按产品信息、人群需求、事实、建议、汇总分类；每项显示 R 编号、适用/不适用条件、缺失处理和正反例。
- 结果行的“为什么这样判断”：实际执行版本、相关 ASIN、来源、条件、结论和核对事项。
- 解释区“未采用的建议”：展示被拦截原因，但不混入正式产品动作列。

界面文字对运营说明业务含义，不默认暴露内部字段名。空数据、无证据、来源失效、加载失败和历史无记录均有独立文案。键盘可打开、关闭、定位详情，窄屏不遮挡表格操作。不增加模块访问权限，也不增加修改规则能力。

先冻结规则与数据契约，再交付查看 UI；两部分均验收通过才算本变更完成，不能将规则展示无限后置。

### 5. 保存兼容与一致性

在现有分析/报告保存载荷中以可选、带版本字段增加 ruleSetVersion、最小规则定义快照及决策记录。实施前核对现有契约是否剔除未知字段，明确生成、保存、重开及导出直接路径；不预设新增数据库表。若必须改变数据库结构，先补充本设计及任务，不顺带迁移。

重开已保存结果使用生成时快照；当前规则目录展示当前版本，两者明确区分。旧报告不回填猜测的决策；显示历史未记录规则版本，显式重新分析才生成新结果。缓存标识包含组织、项目、站点、ASIN 集合、相关输入修订及规则版本，避免跨项目和版本复用。相关字段读取遵守既有项目数据权限，规则说明入口不能绕过模块权限。

## Risks / Trade-offs

- [资料不完整] → 局部说明缺失条件；保留原 VOC 的具体问题和有依据动作，不替换整表。
- [同名异物及标题噪声] → 用用途和结构联合解释，冲突显式化；不承诺仅凭标题准确覆盖全部类目。
- [旧模板从其他消费者重新注入] → 实施前搜索完整动作链路，做跨页面同一输入的一致性测试。
- [规则说明与代码漂移] → 同源条件、稳定 ID、版本及契约测试；检查每个执行谓词有业务展示。
- [历史载荷变大] → 仅保存使用到的规则快照和最小解释，复用来源引用；不自动重采集。
- [权限泄露] → 接口和视图复用现有授权，来源不可用明确提示。
- [共享工作区误改] → 记录限定差异，保留所有无关改动；禁止整站回滚。

## Migration Plan

主题合并及最终功能分层保留上游决策引用；重新解释派生动作时，仅使用该候选来源中的 ASIN 和需求，不再给所有产品寻找任意可用反馈。旧报告字段保持可选，不回填来源。未识别结构条件不自动等同需求相关；动作必须能对应具体引用的问题。动作模板区分温控、质量控制与手部操控，普通照明或亮度调节不推导阅读用途。补充前后轮表达仅作为结构条件覆盖，不能替代按 ASIN 的需求隔离。验收见 additional-asin-validation.md 及第 7 节任务。

### 2026-09-16 原项目回放修正

原七 ASIN 回放发现动作门控之外的结论旁路，本轮补齐流程 03B → 05A → 06/07：

- 人群/场景先按 ASIN 读取就绪记录，再识别原文中的限制、条件、未知和同对象冲突；完整原句始终保留。兼容表格竖线和 VOC 方括号格式，不另建类目硬件模板。
- 摘要只引用该 ASIN 的可用记录，保留完整条件；限制和冲突在表中单列。若仅有限制或缺失，明确人群/场景待核对。混合“适合雪地、不适合冰面”保留完整限定句，不因限制清空有效用途。
- `sourceObservation` 仅允许精确引用本 ASIN 的人群/场景 VOC 原文；不得带硬件 claim、结构条件或新增属性。记录事实是“来源这样描述”，并非产品认证或普遍适用结论。
- 最终定义保留结论 fact 引用后再增加动作 proposal 引用；关键词单列为搜索需求。既有主题占比和机会评分公式不改写，未用语义投影重新计算权重。
- 单复数词形规则和语义解析均纳入规则版本指纹。页面读取共享定义和保存时轨迹，不自行二次判断。

这是有界文本规则，不声称覆盖任意自然语言或仅凭标题识别全部类目；新增表达需补反例、版本说明和回归。当前未引入模型调用、新采集或历史报告重写。
