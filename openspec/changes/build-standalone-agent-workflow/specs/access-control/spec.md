## Purpose

定义公司内部单组织的身份与权限边界，使团队成员能够共享分析项目，同时只有管理员能够管理服务凭据、连接器和系统运行配置。

## ADDED Requirements

### Requirement: 所有业务功能要求登录
系统 SHALL 仅允许已认证且属于当前公司组织的用户访问分析项目、运行状态和报告，并且首版不得开放匿名分析或公开注册。

#### Scenario: 已认证成员访问应用
- **WHEN** 有效的组织成员完成登录
- **THEN** 系统允许其进入团队工作区并访问角色授权的功能

#### Scenario: 匿名请求业务接口
- **WHEN** 未认证请求访问项目、任务、报告或导出接口
- **THEN** 系统拒绝请求且不泄露项目是否存在

#### Scenario: 首个管理员初始化
- **WHEN** 新部署尚不存在任何用户且运维人员执行一次性管理员初始化
- **THEN** 系统创建首个 admin，并在已存在用户后拒绝重复使用该初始化流程

### Requirement: 密码和会话安全
系统 MUST 使用单向密码哈希保存密码，使用安全 Cookie 维持服务端可撤销会话，并限制重复失败的登录尝试。

#### Scenario: 用户成功登录
- **WHEN** 已启用用户提供正确邮箱和密码
- **THEN** 系统创建有有效期的服务端会话，并通过 HttpOnly Cookie 返回不可直接用于读取密码或秘密的会话标识

#### Scenario: 账号被停用
- **WHEN** admin 停用一个成员账号
- **THEN** 系统撤销该账号现有会话并拒绝后续登录

#### Scenario: 连续登录失败
- **WHEN** 同一账号或来源在限制窗口内超过失败阈值
- **THEN** 系统暂时限制新的登录尝试并记录安全事件

### Requirement: 管理员与成员角色
系统 SHALL 至少提供 admin 和 member 两种角色；管理员可管理成员、服务凭据和连接器状态，成员可创建、运行、查看和导出团队分析项目，但不得读取或修改秘密配置。

#### Scenario: 成员启动分析
- **WHEN** member 在团队项目中提交合法 ASIN 并启动分析
- **THEN** 系统创建关联到该成员和组织的运行，并使用管理员配置的服务凭据

#### Scenario: 成员访问管理配置
- **WHEN** member 尝试查看或修改连接器秘密、用户角色或系统配置
- **THEN** 系统拒绝操作，且响应不包含任何秘密值

#### Scenario: 管理员查看连接器状态
- **WHEN** admin 打开系统管理页面
- **THEN** 系统展示连接器是否配置、健康状态和最近错误，但不回显完整秘密值

### Requirement: 团队项目默认共享
系统 SHALL 让同一组织内的成员默认可以查看团队分析项目及其已发布报告，并记录项目创建者和每次运行发起者。

#### Scenario: 成员查看同事项目
- **WHEN** member 打开同一组织内另一成员创建的团队项目
- **THEN** 系统允许查看项目和报告，并保留创建者与运行发起者信息

### Requirement: 记录敏感管理操作
系统 SHALL 审计成员邀请、角色变更、连接器配置更新、凭据轮换和用户停用，并且审计内容不得保存秘密值。

#### Scenario: 管理员轮换密钥
- **WHEN** admin 更新一个连接器的服务凭据
- **THEN** 系统记录操作者、连接器、时间和操作类型，而不记录旧密钥或新密钥内容
