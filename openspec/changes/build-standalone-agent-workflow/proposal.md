## Why

当前网页把 ASIN 数据采集、文件缓存、后台进程、分析规则和页面渲染耦合在同一套本机运行环境中；三个 Skill 虽然随仓库交付，但并未作为可部署、可版本化、可观测的智能体运行。因此应用脱离 Codex/Cursor 并部署到普通服务器或 Cloudflare 兼容环境后，既无法稳定启动后台采集，也无法证明 Skill 的规则被真实执行。

本变更建立一条独立于 Codex 的业务链路：用户创建竞品分析任务，系统采集或读取有来源记录的数据，按确定性规则与版本化 Skill 编排三个分析智能体，并将结构化结果、证据、状态和失败原因交给网页展示。

## What Changes

- 将“输入 3–10 个 ASIN → 创建分析项目 → 补齐数据 → 执行分析 → 生成报告”定义为显式、可恢复的业务流程。
- 引入独立的 Skill/Agent 运行时；运行时读取仓库内的版本化 Skill 源文件，通过模型提供商适配器执行，不依赖 Codex 会话上下文。
- 把三个现有 Skill 定义为有先后依赖的智能体：竞品流量分析、VOC 产品定位、VOC＋关键词最终产品定义。
- 将确定性计算和生成式判断分离：比例、聚合、阈值、排序与数据校验由代码完成，解释、归纳和建议由智能体在结构化输入上完成。
- 把数据采集改为独立的持久化任务流程；Web 请求只创建任务和查询状态，不直接写本机文件、启动 PowerShell 或派生脱离进程。
- 为每次运行保存输入快照、数据来源、Skill 版本、模型配置、结构化输出、错误与重试状态，支持审计和复现。
- 保留已有网页的信息架构，逐步把固定 TypeScript 结论替换为运行结果；迁移期间允许读取仓库已有数据完成最小闭环。
- **BREAKING**：生产部署不再把本机文件系统、PowerShell、浏览器登录态或 Cursor MCP 视为 Web 进程可直接使用的能力；这些能力必须由明确配置的采集器或 Worker 提供。

## Capabilities

### New Capabilities

- `analysis-workflow`: 管理竞品分析项目、运行状态、阶段依赖、失败重试以及从已有数据到完整采集的两种入口。
- `skill-agent-runtime`: 加载、版本化并执行独立于 Codex 的 Skill 智能体，校验结构化输入输出并记录运行元数据。
- `analysis-agent-pipeline`: 编排竞品流量、VOC 定位和最终产品定义三个智能体，并管理它们的输入、依赖、证据与降级行为。
- `data-acquisition-jobs`: 通过独立、持久化的采集任务和连接器补齐 ASIN 数据，公开进度、缺失项、凭据状态与可操作错误。
- `analysis-reporting`: 向网页提供结构化报告、证据来源、置信度、数据边界和导出所需的稳定接口。
- `access-control`: 为公司内部单组织提供登录、管理员/成员角色、团队项目访问和连接器管理权限。

### Modified Capabilities

无。仓库此前没有 OpenSpec 行为规格；现有行为作为迁移基线记录在本变更的设计文档中。

## Impact

- 受影响区域：`app/` 页面与 API、`scripts/` 数据采集脚本、三个 Skill 包、项目/任务存储、测试和部署配置。
- 新增系统边界：Web 应用、持久化任务队列/Worker、Skill Agent 运行时、模型提供商、数据连接器和持久化存储。
- 外部依赖：模型 API；SIF、Sorftime、SellerSprite、Amazon/Alexa 等数据源只在对应连接器启用且具备凭据时运行。
- 部署影响：本地开发仍可使用 Node Worker；生产环境必须提供持久化存储与可执行后台任务，或将采集 Worker 部署到独立 Node 服务。
- 安全影响：API Key、第三方凭据和浏览器会话不得进入前端、Git 仓库、日志或模型提示词。
