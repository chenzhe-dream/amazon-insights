## Context

生产编排器当前只处理三个边界明确的智能体：流量分析和 VOC 定位可并行，产品定义依赖 VOC 与关键词，报告保存和失败恢复由持久化任务机制负责。LangGraph 的价值需要在相同输入、相同 provider、相同失败条件下量化，不能用不同 demo 流程做主观比较。

## Goals / Non-Goals

**Goals:**

- 创建与生产依赖图语义等价、但运行和依赖完全隔离的 LangGraph spike。
- 用同一组 fixture 比较确定性输出、状态轨迹、恢复、幂等、调用次数、Token、费用和延迟。
- 产出可复现实验记录和明确的采用门槛、风险与建议。

**Non-Goals:**

- 不实现生产框架迁移、双写、灰度或 UI/API 集成。
- 不修改现有数据库 schema、任务租约、报告合同或 Skill。
- 不使用生产凭据、真实客户数据或不可控的实时连接器。
- 不预设 LangGraph 必须胜出。

## Decisions

### 1. spike 与生产代码路径隔离

实验代码使用独立入口、独立依赖边界、fixture provider 和临时检查点存储。生产 package/runtime 不导入实验模块，生产启动命令也不发现或执行它。

### 2. 两种编排使用同一测试矩阵

静态编排基线和 LangGraph 原型 SHALL 消费完全相同的版本化 Skill fixture、输入快照、provider 响应、时钟、ID、失败注入和预算。比较项包括：最终结构化结果摘要、节点执行顺序、状态转换、重试次数、报告版本、恢复后重复调用、Token、估算费用、墙钟时间和持久化写入次数。

### 3. 确定性与恢复优先于代码行数

同一 fixture 重复执行必须产生相同的业务结果和可解释状态轨迹。进程在每个节点边界崩溃后，恢复不得重复已经提交的模型调用或报告发布。若框架需要额外的幂等层、隐藏写入或难以审计的序列化状态，实验必须如实记录。

### 4. 成本使用完整账本

实验统计框架触发的每次模型请求、修复重试、检查点、序列化负担和恢复重放。成本比较同时报告绝对值和相对静态基线的差异，不只报告成功路径延迟。

### 5. 采用需要新的 OpenSpec change

spike 只输出 `adopt`、`do-not-adopt` 或 `needs-more-evidence` 建议。即使建议采用，也必须另建 change，重新说明生产依赖、数据迁移、回滚、监控和发布门槛；本 change 不授权生产代码变化。

## Experiment Matrix

- 完整输入成功路径与允许并行的两个前置智能体。
- VOC/关键词缺失导致 `waiting-input`。
- 单节点临时错误、永久错误、结构错误和预算超限。
- 在每个节点执行前、模型响应后、检查点后和报告发布后模拟进程崩溃。
- 重复提交、重复恢复、乱序完成和取消。

每个场景至少使用固定种子重复运行，并保存两个编排器的规范化轨迹与差异。

## Exit Criteria

实验报告必须能够复现，列出版本、fixture digest、运行环境和度量方法。若任一方案出现业务结果不一致、恢复后重复付费调用、状态不可解释或成本不可接受，报告必须将其标记为阻断项。没有后续 adoption change 时，生产继续使用静态编排。
