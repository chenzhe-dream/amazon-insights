# 商品形态与价格带：Sorftime 接入验收稿

## 本次确认事项与完成结果

| 用户确认 | 已实现 | 与原版业务流程关系 |
| --- | --- | --- |
| 商品池先用 Sorftime | 新任务从 category_report 获取头部商品；100以上按原版 product_search 扩展，同类目和排名过滤、跨页去重，最大300 | 直接输入类目、点击筛选，来源到位即展示；不要求预填形态目录 |
| 补商品历史销售额 | 每个固定 ASIN 独立保存 SalesVolume、SalesAmount 和图片来源；页面直接显示最近月份并提供趋势提示 | 不用当前价格乘历史销量冒充商品历史销售额 |
| 接通毛利与准入 | 读取 gross_profit_margin，按原版70/60/50百分比阈值输出优先、建议、谨慎、不建议进入 | 是 Sorftime 平台费后毛利初筛，不是净利润；无来源值保留未知 |
| 其他按原版 | 七区、年份/品牌/形态/准入/价格带筛选、批量形态、样本移除恢复、周期排序、列宽保存、10单位价格带和原版纯规则结论 | 人工修改立即更新草稿；保存只负责形成可恢复的数据库版本 |

业务顺序：输入类目与月份 → Sorftime 商品池 → 独立采集类目与商品历史/图片 → 展示七区 → 在商品表调整形态或样本 → 即时重算 → 可选保存版本。

七区顺序为：类目销量看板、TOP销售商品、上架年份、商品形态销量、形态价格带、品牌价格带、综合结论。没有引入 Agent 步骤或人工保存前置门槛。

## 保留的工程边界

- 新任务使用 rules-v4，旧 rules-v1/v2/v3 任务保留其原有商品池、口径、重放与历史版本，不自动迁移或重采。
- 来源与版本仍存入数据库；校验组织身份、请求范围、来源指纹、父修订及幂等命令。单个失败项可重试，旧保存版本不会被新的来源结果覆盖。
- 近3/6个月按原版取研究结束月之前最近返回的3/6个历史点；固定2024/2025年度列保留。上游没有返回的月份不补零，年度结果可能仅覆盖实际返回的月份。
- 已确认上市前的年份显示不适用，对汇总没有销量贡献；上市后的缺失和未知上市时间继续显示未知。该规则不改写已保存的原始历史值。无效上市日期不用于推断；若上市前年份出现正销量，标记日期冲突并暂停相关年度结论。
- 类目销售额趋势仍是原版销量×历史均价估算，页面明确标注估算；商品历史销售额则是独立 SalesAmount 返回值，两者区分。
- 调整商品池上限会新建采集任务；单纯查看、筛选、修改形态、保存/读取版本不会重新采集。

### 容量验证（模拟上游 + 真 PostgreSQL）

300商品、每商品24个月，12次扩展搜索、920步骤、919次模拟来源调用。完整执行约318秒；本机单次读取1984ms、保存4016ms、恢复版本3800ms、重读1935ms。响应约1.68MB。另以300×120月合同通过8MiB有限响应预算测试；小接口仍维持原响应限制，形态报告读写有60秒截止。

这些数字只描述本机测试。真实300商品尚未整批采集；供应商是否返回足量、上游限速及每个商品历史长度仍决定实际覆盖和耗时。

### 自动化及交互

- 原版同输入纯规则对比、未知/零/新品不适用、七区渲染、金额独立可见。
- 隔离数据库：父版本、重复命令、组织隔离、销售额与图片失败后重试、旧版本冻结。
- 浏览器：修改/保存/重读/历史只读、品牌筛选、批量形态、容量重采回调；300行及搜索可用，页面无脚本错误。
- 类型检查、生产构建和 OpenSpec 严格校验通过（具体命令见 verification.md）。
