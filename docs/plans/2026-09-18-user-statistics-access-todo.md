# 待办：用户与使用统计的模块开关与查看权限不一致

- 记录日期：2026-09-18
- 状态：2026-09-21 用户确认后已完成本地修复及验证，未发布。原始问题与验收清单保留如下；实现记录见 `docs/repairs/2026-09-21-statistics-view-grants.md`。
- 用户决定：当前额度有限，先记录，后续再修复。
- 范围：用户与使用统计的授权及配置交互；本次仅新增文档，不修改代码、账号权限或正式服务。

## 现象与已核实原因

管理员为普通用户勾选“用户与使用统计”并保存后，该用户仍看不到入口。
本次只读检查确认：目标账号正常，个人模块配置已保存为 9 个模块，包含 `admin-users`（配置版本 2），但不属于系统所有者或现有指定查看账号。

当前入口要求同时满足 `canViewUserPresence` 和 `visibleModules` 包含 `admin-users`。模块保存接口仅更新可见性，不授予统计查看资格。后端统计接口也独立检查查看资格，所以仅调整前端或刷新页面无法解决。

同时，`canManageModuleVisibility` 当前复用了统计查看资格。未来若直接扩展同一判断，可能连配置其他人模块的能力一起开放。

## 定位入口

- `app/auth-session-gate.tsx`：统计入口的双重判断。
- `app/admin/users/admin-users-page.tsx`：统计展示与模块管理入口。
- `app/admin/users/module-visibility-panel.tsx`：勾选界面和保存提示。
- `server/auth/user-presence-access.ts`：系统所有者及指定账号的查看资格。
- `server/routes/auth.ts`：会话返回查看资格，并复用为模块管理资格。
- `server/routes/usage-analytics.ts`、`server/routes/admin-user-presence.ts`：后端查看权限。
- `server/routes/module-visibility.ts`、`server/db/postgres/module-visibility-store.ts`：配置授权、模块保存和审计。

## 后续修复建议（待实施前确认设计）

- [ ] 拆分“查看用户与使用统计”和“配置其他人的模块”两种权限，明确授权人及组织边界。
- [ ] 为统计查看提供明确授权入口，或在现有配置中明确区分“显示模块”和“授予查看权限”；让保存后的提示反映实际生效结果。
- [ ] 明确统计查看覆盖的人员信息、使用数据及组织范围；不因开放统计而自动授予管理权限。
- [ ] 梳理历史配置迁移：旧用户可能默认拥有全部可见模块，不能直接将 `admin-users` 已勾选视为已获统计授权，不能删除资格检查后全量放行。
- [ ] 保留系统所有者及现有合法查看者的访问能力，支持授权、撤销和审计。
- [ ] 同步会话、导航、页面和后端接口判断，并明确保存后刷新或会话更新的生效方式。

## 验收条件

- [ ] 普通用户被明确授予查看权限且模块可见后，刷新可看到入口并读取允许范围内的统计。
- [ ] 只有可见性、没有查看授权的用户，界面清楚说明原因，后端仍拒绝访问。
- [ ] 获得统计查看权限不获得模块配置、人员管理或其他管理能力。
- [ ] 撤销查看权限后，入口及接口按会话更新机制同步失效，直接访问接口不可绕过。
- [ ] 历史默认全选、新用户默认设置不产生批量意外授权；跨组织访问被拒绝。
- [ ] 系统所有者和原有合法查看者保持可用；授权变更可追溯。
