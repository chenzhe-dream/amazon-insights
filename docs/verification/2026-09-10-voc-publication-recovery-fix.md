## Root cause

1. **Cumulative publication ordering.** `manualAlexaVoc.listAtCutoff` returns lexical ASIN order; the snapshot contract requires records to follow the trusted project's target ASIN order. Existing integration fixtures used lexical target order and masked this. Parent's pure candidate build from the scoped production revisions returned `ZodError` at `records.alexaVoc[1].asin`: `VOC records must be unique and follow target ASIN order`. Production target order was B0CQY5RK52, B08T1N86Q5, B06VSQQ3SD. No provider execution or snapshot insertion was used for that diagnostic. The revision transaction had already committed, while the terminal/snapshot/wake transaction rolled back. The next ASIN was never reached.
2. **Error isolation.** The worker immediately rethrew every retryable publication error. A known snapshot publication conflict therefore also prevented an eligible sibling from running, although the affected item's revision was already durable.
3. **Retry ordinal collision (parent-owned fix).** Appending an input can allocate another attempt while the predecessor still runs. After both publication attempts fail, the old pending predecessor can be selected first and try inserting its already occupied next attempt number. The parent changed normalization-only allocation to the next free ordinal while preserving the logical cycle and remaining retry allowance. Other stages retain their existing behavior.

Running positioning alone was an explicitly rejected hypothesis: the original lexical-order real SQLite/PostgreSQL cases both passed. The reversed-order cases reproduce the actual defect, including C queued while B is executing and positioning already runs. The run cutoff was not the cause: parent verified both durable revisions' captured timestamps equal the run cutoff. Positioning's separate upstream model failures are not attributed to normalization.

## Changes and safety boundaries

- Order both cumulative normalized records and their per-ASIN provenance by the trusted target list. Reject duplicate targets, duplicate returned revisions, or revisions outside the target list; do not silently drop malformed associations. Existing snapshot, actor, organization, project, run, lease, fingerprint, and audit checks remain in place.
- Only a typed `DataSnapshotConflictError` from the post-durability publication boundary becomes `AlexaVocPublicationConflictError`. Continue the remaining prepared page, then rethrow for the existing bounded retry policy. Never synthesize a terminal for the missing publication or enter finalization with a deferred failure.
- Replay uses the same verified durable revision/audit path and never invokes the model or allocates another revision. Unknown storage failures, connection/timeouts, integrity/subject failures, and lease/authority errors do not acquire permission to execute siblings through the new isolation path.
- Explicit worker configuration/authentication/cancellation and lease-loss errors now stop the page. Check the abort signal before preparation and before each item, including replay.
- No timeout or global budget increase; no schema, UI, provider, or wake-scheduler change in this Task 2 worker's code. Task 1 has separately owned schema/UI changes in the shared worktree.
