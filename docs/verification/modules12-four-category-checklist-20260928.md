## 缓存规则与待业务决策

| 入口 | 已核实当前规则 | 本轮是否修改 |
|---|---|---|
| 总览基础“筛选市场” | 成功后再次提交创建新基础任务；幂等编号只保护同次提交 | 否 |
| 总览读取保存报告 | 同组织、站点、完整类目路径、结束月/周期、TopN、新品窗口匹配；无天数限制；返回保存的起始月 | 否；保存时限待业务确认 |
| 总览重新采集 | 新研究与新任务，不复用旧报告作为采集结果；同次请求不确定失败仍保留幂等编号 | 修复已发布，本轮将入口与时间信息显式展示 |
| 商品形态普通查询 | 同用户/组织及匹配查询、版本；活动任务复用；有商品的成功任务按创建时间7天内复用 | 否 |
| 商品形态重新采集 | forceRefresh绕过候选缓存；同命令重试仍幂等 | 否 |
| 关键词普通查询/强制刷新 | 本地查询指针按任务创建时间7天，按登录身份隔离；强制刷新绕过查找 | 否；仅核实规则，不纳入本批模块完成度 |

查看历史不续期。任务创建时间只说明当前任务何时建立，各来源可能稍后采集，供应商统计更新日期另看来源。业务待定的是总览报告复用时限，不擅自改为7天或永久有效保证。

## 剩余队列与推进顺序

1. 本轮缓存入口：页面、失败重试、并发防重、历史不变回归 → 正式发布 → 实际入口截图 → 用户测试。
2. 模块二表格/趋势：已实现修复待用户确认；确认后关闭对应验收项，不再次改统计规则。
3. 模块一总结/来源：用落地灯及滑板车分别验收完整、部分缺失样本。旧报告继续读取，新来源能力需要重新采集。
4. 外部缺口：按D1—D5逐项保留证据；供应商更新/业务口径未确认的保持待确认，不通过UI或默认0掩盖。
