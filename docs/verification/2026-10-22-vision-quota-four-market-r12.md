## 结论

**不是当前调用 Key 的钱包余额耗尽。**供应商公开 Key 用量页面使用 `GET /v1/usage`；本轮使用候选同一个 Key 调用该接口，HTTP 200，返回 `isValid=true`、`mode=unrestricted`、`remaining=603.76194355`、`unit=USD`、`planName=钱包余额`。这能排除当前 Key 钱包余额归零，不能证明供应商内部图片转写子服务的账户、额度或配置正常。

四站原 24 个 ASIN 范围内，已取得的静态图库共 135 张，全部逐张重新请求图片接口，没有用缓存命中冒充新请求。135 次均返回 HTTP 200，但原始回复均为整图不可识别或转写服务不可用，没有真正的视觉分析。因此图片上游故障仍未修复，四站完整图片分析不能验收通过。

## 本地修复

完整批次额外复现 3 条假成功：美国和英国各一条“当前图片无法识别”，德国一条“图片转写与画面识别服务不可用”。旧规则漏掉了“当前”前缀及复合服务名称。这 3 条仅存在独立诊断证据中，未进入业务缓存。

增加上述 3 条实际回复作为失败用例，先得到 `Missing expected rejection`，再修复规则。整图不可识别允许“当前”前缀；图片/图像/画面/视觉的识别与转写组合服务名称统一识别。正常的“当前图片展示蓝色支架……无法确认尺寸材质”仍允许。

新响应校验、旧缓存复核、就绪计数继续使用同一个有效性规则；普通任务不会自动无限重试已知无效输出，显式修复仍保留重试能力。严格 JSON 合同保留；诊断中解开 content/value 包装仅用于检查故障语义，没有把这种包装当作合格业务输出。

四站 135 份原始响应使用修复后的解析器离线重放：135/135 拒绝，135/135 能定位到明确故障文本，纠正 3 个假成功。离线重放单独标记，不计作第二轮付费请求。
