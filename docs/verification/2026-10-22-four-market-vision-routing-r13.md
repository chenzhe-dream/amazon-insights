# 四站图片分析修复与候选验证 R13

日期：2026-10-22。验证范围仅限 33900/33901，本任务未发布 31900/31901。已取得的 135 张静态图片最终全部通过真实分析、保存和当前显示版本审计，可进入人工验收；英国缺完整图库的 4 个商品和原有评论覆盖限制仍然存在。上游经过重试才补齐，不能宣称首次请求全部成功或长期稳定性已验证。

## 本轮找到的原因

1. **不是余额耗尽的证据。** 起始供应商查询余额约 602.71 美元，文本控制请求可用，视觉请求却返回“无法识别／图片转写服务不可用”。换成 gpt-5.6、gpt-5.6-sol，图片 URL 和图片内容对照仍不能识图。这说明单纯换版本不能解决当前供应商通道的问题。
2. **接口协议与供应商分组有关。** 测试密钥在多个分组做了有限对照。部分分组返回“没有可用账号”；GLM 分组通过 `/v1/messages`、公开别名 `claude-sonnet-5` 能生成真实图片描述，通过 Chat Completions 则拒绝请求。只能确认该分组、协议和别名可用，不能据此确认供应商内部实际模型或转发映射。
3. **还存在图片 URL 解析问题。** 英国 `B0GHQW7GYY` 的第 2 张图，URL 输入返回 HTTP 400、上游代码 1210“图片输入格式／解析错误”；同图直接传 JPEG 内容返回 HTTP 200、`end_turn` 和具体的品牌对比图备注。对照文件：`failed-image-diagnostic-UK.json`、`failed-image-diagnostic-data-UK.json`。这证明该张图可以绕过 URL 解析问题，不代表此前所有 502 都有同一原因。
4. **发布校验误判。** 对同一图片重新分析，分类标签从 3 个变成 1 个，被通用数组长度保护当作丢失数据。修复限定在“同 URL、有效备注、非空分类标签”的重新分类；备注缺失、不可识图文本、标签清空、URL 不一致及其他元数据丢失仍被拒绝。

官方 API 停用清单与模型文档没有为“GPT-5.5 已全面停用”提供依据。供应商转发状态、ChatGPT/Codex 中可选模型和官方 API 生命周期不能混为一谈。参考：[OpenAI 停用说明](https://developers.openai.com/api/docs/deprecations)、[GPT-5.5 API 文档](https://developers.openai.com/api/docs/models/gpt-5.5)。

## 实现与隔离

- 图片调用新增独立协议、地址、模型、密钥配置；显式独立视觉通道缺少图片密钥时不会借用文字分析密钥。原有默认 OpenAI Chat 路径保留。
- 新增 Messages 响应处理：只解析最终文本，不把 thinking 当答案；要求正常结束，拒绝截断、包装错误和“图片不可用”的伪备注；只允许单个完整 JSON 代码块。
- 候选启用 `base64` 图片输入：仅下载 `https://m.media-amazon.com/images/I/` 的 JPEG，禁止重定向，20 秒图片读取期限，5 MiB 流式大小上限；校验类型和文件头。下载请求不带供应商密钥；来源失败独立标记为 `image-source`。保存记录仍以原始图片 URL 标识图片。
- 不改变图片队列的并发和超时策略，不增加自动无限重试。本轮失败 ASIN 最多做 3 轮正常任务重试；支持的操作会重新分析该 ASIN 的整组图片，因此总调用数大于 135。
- 只有用户指定的“测试”密钥改到已验证的 GLM 分组；“Amazon选品”密钥分组不变。密钥保存在候选专用本地文件，不写入代码或报告。
