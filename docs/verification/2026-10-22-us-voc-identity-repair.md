# 31900 美国 VOC 导入配置身份修复

## 已证实的原因与范围

目标为美国项目 `7e948748-e794-4322-ab19-c11d3bca328f`，运行 `598169f3-8042-4793-aea9-bef2f22b2051`，ASIN `B0G7BK6ZF6`。正式运行代码 `1dac83bd`，响应模式 `json_object`。

输入快照 `18dd3ba1-04e2-4d60-9b97-89d9b32f39d5` 保留了 9991 字节、293 行原文。离线解密校验确认输入没有超过长度限制，但展开表格和扩展标题不能通过严格格式解析，正确进入模型标准化分支。导入入口指纹没有 `:json-object`，Worker 的身份包含该后缀，执行身份校验在模型调用前失败。该运行当时没有标准化 agent_run、终态或成功版本。前端将缺少终态的 configuration 错误误标为 persistence。

## 修复方案

1. 在配置解析时纳入响应模式，入口和 Worker 复用同一身份；保留完整身份校验，不兼容放行旧指纹。
2. 状态接口将执行前 configuration 错误单独分类，页面提示服务配置异常、原文已保存，避免要求用户反复修改文本。
3. 不放宽固定解析器，不将报告百分比转成虚构评论数量。恢复时只对目标 ASIN 取出已保存原文，通过标准导入服务创建新身份的输入，保留旧快照和失败审计。
4. 仅正式 31900/31901 使用受管发布；其余候选环境不切换。发布前检查空闲并备份，发布后验证精确版本与实际持久化结果。
