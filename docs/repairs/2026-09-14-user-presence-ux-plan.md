## 推荐页面方案

沿用现有主页蓝白风格和“用户状态 / 使用统计”入口，只优化用户状态视图。

1. 顶部显示人员总数、近期有活动人数、未登录人数；点击状态可筛选。
2. 单行工具栏：姓名/账号搜索、活动状态筛选、账号来源筛选、刷新。默认只显示钉钉人员，可切换全部或历史本地账号。
3. 列表精简为人员、活动状态、角色、最后活动、最后登录、操作六列。人员一格展示姓名与钉钉标识，长账号作为次要信息；日期不强制占用大宽度。
4. 点击“登录记录”在该行下方展开详细记录，移出主表的会话到期、登录次数等次要信息。提供明确的展开/收起状态。
5. 底部分页：总条数、当前范围、上一页/下一页、页码、每页 10/20/50 条，默认 10。搜索、筛选及每页数量变化时返回第一页；刷新尽量保留当前条件，删除后校正越界页码。
6. 默认最近活动靠前，以稳定用户标识作为排序兜底；按当前组织和原授权规则访问。分页、总数和筛选由后端负责，跨页搜索不是只搜索当前页。
7. 空列表、无搜索结果、初次加载、刷新失败分别展示；刷新失败保留上一次成功内容并提示。窄屏显示人员卡片与同样的分页操作，避免九列横向拖动。
8. 保留“近期活动”这一准确表述，不将系统使用状态称为钉钉在线。管理标签与 URL 同步，刷新后留在当前视图。

页面顺序：标题和返回主页 → 管理标签 → 状态概览 → 搜索筛选 → 人员列表 → 分页。

可选简化方案是只做前端分页，改动更小，但仍需一次加载全量人员与最近登录记录；本次推荐后端分页。整页重建成独立管理系统没有必要。

## 账号清理核对（当前数据库快照）

同一组织现有 22 个账号：6 个绑定钉钉、16 个未绑定钉钉。所有账号的数据库状态均为 active，没有 disabled 账号。因此“未启用”需要明确为未使用的历史账号，不能按禁用状态直接删除。

未绑定钉钉且没有任何会话记录的账号共 10 个。逐项扫描所有指向 users 的数据库外键后：

| 处理建议 | 账号 | 原因 |
|---|---|---|
| 可清理候选（7 个） | Ops Admin 2、Ops Admin 3、Ops Member 1–5 | 未绑定钉钉、无登录记录、无数据库外键引用 |
| 保留 | Local VOC operator | 关联项目和分析运行 |
| 保留 | Test Member 2、Test Member 3 | 关联审计记录 |
| 暂不删除 | 其余 6 个未绑定钉钉账号 | 有登录历史，未纳入本次未使用账号定义 |

确认后：先备份，再在事务中锁定这 7 个具体账号，复核身份、会话和外键引用；条件有变化则停止该账号删除。删除数量与账号名单写入验收记录。保留已绑定钉钉身份及历史业务/审计数据。本次不顺带关闭本地应急登录，也不增加批量删除管理功能。
