# 钉钉人员模块可见性方案

状态：按用户最新澄清修正，尚未改应用代码或实际人员配置。本版取代此前扩展到业务操作、接口数据和任务权限的方案；不再需要选择只读/可操作等级。

## 用户确认的范围

按钉钉人员配置模块“显示 / 隐藏”，对应截图中的九个入口：市场调研、竞品概览、VOC、关键词调研、新品定义、立项前确认清单、竞品流量分析、收藏夹、用户与使用统计。

父模块开关同时控制子菜单和对应页面区域。关闭后隐藏导航、快捷入口及页面内容；手动输入旧链接也不挂载该模块，转到首个可见模块或提示暂无可见模块。收藏中的跳转入口遵守同样的页面显示规则。

这是界面可见性设置，不将其描述为后端数据隔离。原业务 API、分析队列、共享数据依赖、导出及组织/项目权限逻辑不在本次改动范围。

## 配置界面

在现有管理页面增加“模块可见性”配置入口：

搜索钉钉人员 → 配置可见模块 → 勾选模块 → 保存。

沿用当前人员搜索、分页和蓝白样式。按人直接配置，不引入部门、岗位、角色模板或多级权限。配置入口只对现有被授权的管理人员开放，不能通过显示某模块获得额外管理权限。

“用户与使用统计”的显示条件为：原查看资格通过，并且个人显示开关开启。开启显示开关不能突破原有统计查看限制。

## 接入方式

- 沿用 auth_identities 中绑定的本地 user_id 确认人员，不按姓名判断，也不重新对接钉钉通讯录。
- 原数据库保存每人的可见模块列表。配置读写接口验证真实会话、现有管理资格及组织范围。
- 登录会话提供可见模块配置。统一映射 app/page.tsx 的八组业务导航、app/lib/app-tabs.ts 中子页面和用户统计入口。
- 前端过滤菜单、快捷入口及页面挂载。保存后返回服务器确认结果；用户下次读取会话或刷新页面时应用配置，不增加定时心跳。
- 无个人配置时沿用现有可见范围，不因这次界面改造自动限制现有或新登录人员。显式空列表表示无可见业务模块。

## 实施与验收

1. 添加模块目录、个人配置存储和管理读写接口。
2. 接入配置面板、会话返回与统一前端显示判断。
3. 验证两个人看到不同菜单、父模块与子页面同步、旧链接与收藏入口、保存取消、组织隔离及原统计查看限制。
4. 类型检查、原分析/统计定向回归和构建通过后，备份数据库并通过现有受管流程更新本地服务。

本次不改分析引擎，不限制后台任务，不引入业务 API 模块授权体系。
