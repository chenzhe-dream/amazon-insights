# 历史项目列表优化与服务端分页

用户需求：优化历史项目列表，并使用后端分页查询。

## 实现

- 默认每页 10 条，可切换 20 / 50 条；首页、上一页、下一页、末页及结果范围。
- 两行展示项目名称、站点、类目，以及 ASIN、创建人、更新时间；超过三个 ASIN 折叠为数量，悬停可查看完整内容。当前项目单独标记。
- 保留搜索和类目下拉，移除重复的整排类目快捷按钮。搜索防抖 300ms；修改搜索、类目、范围和每页数量时回到第一页。
- 使用现有经过认证的 Agent GET /v1/local-data/projects；新增可选 page/pageSize/search/category/view 参数及 pagination 返回信息。未携带分页参数的已有调用仍返回完整列表，兼容现有来源项目选择等调用。
- 服务端先按收藏、搜索、类目过滤，再按更新时间和 ID 稳定排序、截取一页。收藏范围来自当前认证用户所在组织，客户端不能指定组织。
- 列表更新时取消旧请求，阻止旧响应覆盖新页；项目删除或取消收藏导致页码越界时回到最后一个有效页。删除失败保留当前记录和提示。

## 数据边界

沿用现有历史项目文件和组织收藏标记，不迁移数据库。本次实现的是服务端接口分页：浏览器仅接收一页；服务端仍读取现有项目元数据完成查询。当前规模无需新增存储系统。

## 验证

- local-data-bridge + project-library-pagination：34 项通过，含实际 Agent HTTP 参数验证、分页、组织收藏范围、筛选顺序和越界处理。
- analysis-project-favorites-ui + project-delete-page：9 项通过，覆盖保存、收藏、删除失败/成功、分页搜索、调整页大小、刷新后收缩页数及原页面删除生命周期。
- npm run typecheck：通过。
- 浏览器测试使用隔离数据；桌面及 390px 窄屏截图已检查。

## 手工验收

打开收藏夹中的历史项目，验证第一页最多 10 条；翻页后搜索 ASIN，应回到第一页并返回跨页匹配结果。切换每页 20 条、已收藏和类目筛选，核对总数及加载项目功能。

## 时间展示和排序（后续确认需求）

- 开始时间取项目 createdAt，编辑不改变。列表显示完整年份、月日和时分。
- 增加开始时间最新/最早、修改时间最新/最早四项排序，默认修改时间最新。切换后回第一页，服务端先对全部筛选结果排序，再分页。
- updatedAt 缺失、无效或与开始时间相同，显示“未修改”，排序使用开始时间；正常修改使用最后修改时间。按时间戳比较，兼容不同时区表示。
- 新建项目保持 createdAt 与 updatedAt 相同；自动补齐历史链接、查询时补类目保留更新时间；显式编辑继续更新时间。
- 历史项目沿用已保存的时间，不批量猜测或改写过去的修改记录。
- 验证：35 项接口/查询测试、4 项存储测试、10 项浏览器回归测试、全仓类型检查通过；桌面与窄屏展示检查通过。
