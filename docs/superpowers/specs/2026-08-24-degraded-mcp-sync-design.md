# MCP 降级运行设计

## 目标

保留现有的“开始全自动分析”按钮。分析全新 ASIN 时，哪个 MCP 数据源可用就运行哪个；某个数据源故障不能阻塞其他相互独立的数据源，也不能把缺失数据展示成完整结果。

## 运行规则

- 提交任务前，分别检查 SellerSprite、SIF 和 Sorftime 的状态。
- 待执行阶段所需的数据源中，只要至少有一个可用，就允许创建任务。
- 已知不可用的数据源不再发起调用，其负责的阶段标记为 `partial`，固定提示“数据源不可用”。
- 可用数据源只处理用户本次提交的站点和 ASIN，不得替换成其他 ASIN。
- 如果数据源在运行途中故障，停止该数据源后续调用，把其剩余阶段标记为 `partial`，继续运行其他数据源。
- 只有待执行阶段所需的数据源全部不可用时，才拒绝创建任务。
- 图片 AI 和需要人工处理的 Alexa 流程保持现状。

## 页面提示

提交前，页面提示哪些数据源不可用、会缺少哪些模块，并说明可以继续分析，但最终结果将是“部分完成”。仍然只保留现有的“开始全自动分析”按钮，不新增按钮。

运行期间和结束后，被跳过或执行失败的阶段继续显示，并标明具体原因。只要存在不可用的数据源阶段，任务最终状态必须是“部分完成”，不能显示为完整完成。

## 安全与测试

- 不得为不可用的数据源伪造商品底库或模块数据。
- 不得用关联 ASIN 替换用户提交的目标 ASIN。
- 用户单击一次只能产生一次提交、一个任务和一个 Worker 领取记录。
- 回归测试覆盖：三个数据源中两个可用、仅一个可用、全部不可用、运行途中故障、页面提示内容、ASIN 范围保持一致，以及三个数据源全部正常时行为不变。
