# 图片发布刷新与完成度表达设计

## 目标

当图片图册与 AI 备注已经生成并发布后，浏览器必须加载对应的 Web artifact，展示 Provider 实际返回的全部图片与全部可用备注；终态页面必须区分“流程已结束”和“数据完整度”，不得用 100% 暗示数据完整。

## 已确认事实

- 绑定任务 `e49f2bf3-fb26-4d90-811f-4a2e665f1efc` 实际生成 20 张图片：三个 ASIN 分别为 7、7、6 张。
- 图片 AI 备注实际完成 20/20，三个 ASIN 的备注分别为 7、7、6 条。
- 新 artifact 已发布并由 Web 提供，但浏览器在 Web 切换窗口后仍保留旧 bundle，因而只显示旧的单图与“缺少 AI 备注”。
- “执行进度 100%”当前表示自动流程已经终止；真实数据完整度为 80%。两者并列仍会让运营误读为完整成功。

## 方案

### 1. 有界 artifact 收敛

- 终态 publication 为 `applied` 时，以 `publication.artifactId` 为目标版本。
- 页面先比较当前文档的 `data-web-artifact-id`；一致则不刷新。
- 不一致时触发刷新。刷新后的页面继续通过正式 job GET 恢复，并再次比较 artifact。
- 仅在目标 artifact 尚未加载时进行有限次数、有限时间的重试；达到上限后停止自动刷新并显示“新数据已发布，请手动刷新”。
- 不创建新 job/run/stage，不调用 Provider，不清除终态任务指针，不形成无限刷新循环。

### 2. 图片显示与备注对账

- 图片矩阵继续以 Sorftime `galleryImages` 为第一来源，展示 Provider 返回数组中的全部非空、去重图片，最多遵循现有 9 列界面上限。
- 每个 ASIN 明确显示“Provider 返回 X 张 · AI 备注 Y/X 张”。
- `Y < X` 时显示对应缺口原因；不得显示图片备注完整。
- Provider 返回少于 Amazon 前台实际图片的问题不在本切片引入新抓图渠道；页面只陈述本次 Provider 返回数量，不声称覆盖 Amazon 的全部媒体。

### 3. 终态进度表达

- 非终态继续显示执行百分比和剩余时间。
- `completed`、`completed-with-gaps`、`failed` 等终态不再显示“执行进度 100%”，改为“流程已结束”。
- 数据完整度继续独立显示百分比；存在缺口时保留逐 ASIN、逐模块原因。
- 图片备注必须纳入完整度：每个 ASIN 只有在该 ASIN 的 Provider 图片均有终态备注结果，且全部为 `ready` 时才计为图片备注完整。

## 错误处理

- artifact 检查或刷新失败不改变业务任务终态，不自动重新分析。
- artifact 重试用页面会话内状态约束，不写数据库、不写永久浏览器存储。
- 图片数组为空、备注缺失、备注超时或连接失败均保持现有安全原因码和中文提示。

## 验收

1. publication applied、浏览器 artifact 落后时，有限刷新后加载目标 artifact；已是目标 artifact 时零刷新。
2. Web 切换期间首次刷新未收敛时可以再次恢复，达到上限后停止并提示手动刷新；不存在循环。
3. 当前批次展示 7、7、6 张图片和 7、7、6 条 AI 备注，共 20/20。
4. 终态显示“流程已结束”和真实“数据完整度 80%”，不再显示“执行进度 100%”。
5. 备注少于图片时，数据完整度下降并显示每个 ASIN 的 X/Y 与固定缺口原因。
6. 不新增 Provider 请求，不改变同步、并发、租户隔离和任务生命周期合同。
