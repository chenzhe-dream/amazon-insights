# Alexa VOC 短报告导入修复设计

## 背景

当前 Alexa VOC 手动导入在前端和 API 中都设置了 600 字硬限制。短于 600 字的有效报告会在前端被静默拦截，而按钮仍呈现可点击样式，用户会看到“点击没有反应”。600 字不是 Alexa 数据格式要求，也不能可靠代表报告是否完整。

## 方案比较

1. 将阈值从 600 调低到固定字数：改动最小，但仍可能误拒绝有效短报告。
2. 仅拒绝空白输入，由现有解析管线判断内容是否可解析：不会按篇幅误判，并能复用真实业务规则。采用此方案。
3. 在提交前完整复制解析器到浏览器端：反馈更早，但会造成前后端规则重复，不适合本次小修复。

## 设计

- 前端按钮仅在请求进行中或输入去除空白后为空时禁用。
- API 仅拒绝空白报告，返回清晰的中文错误；不再检查固定字符数。
- 非空但结构无效的文本继续进入现有 `saveAlexaVocToSystem` 解析管线，由解析器返回具体失败原因。
- 自动抓取脚本的完整性门槛保持不变。本次只处理用户手动粘贴入口，避免放宽自动抓取对页面残片的识别标准。

## 验收与测试

- 少于 600 字但非空的手动报告能够发起请求，不再被前端静默拦截。
- API 接受少于 600 字的非空请求并调用解析管线。
- API 仍拒绝空白文本。
- 请求处理中按钮保持禁用，避免重复提交。
- 现有构建和相关测试通过。
