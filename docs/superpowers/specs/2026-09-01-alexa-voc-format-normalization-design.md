# Alexa VOC 输入格式归一化设计

## 目标

运营人员可以直接粘贴 Alexa for Shopping 生成的七问报告，不需要手工删除 emoji、编号、Markdown 标记或括号说明。系统先识别并归一化标题展示格式，再沿用现有严格 VOC 合同完成导入。

## 已确认问题

真实报告使用 `🎯 #1 顾客关注点 (客户最在乎什么)`、`✅ #2 好评点 (...)` 等标题。当前解析器仅接受 `1`、`1️⃣` 等编号，因此七个完整维度全部被识别为缺失，导入返回 422。

## 设计

### 输入归一化

标题识别边界只忽略无业务含义的展示字符：

- 可选 emoji；
- 可选 Markdown 标题标记；
- `#1`、`# 1`、`1`、`1️⃣` 等 1–7 编号；
- 编号后的常见分隔符；
- 标准维度名称后的圆括号说明。

归一化后仍只接受现有七个标准维度及既有明确别名：顾客关注点、好评点、差评点、未被满足的需求、使用人群、使用场景、核心购买动机。各段正文继续由现有结构化解析与限额合同处理，不要求固定表格或固定句式。

### 安全边界

- 不使用模糊关键词或 AI 猜测把任意文章映射成 VOC。
- 继续要求所选 ASIN 的绑定合同与至少三个有效标准维度。
- 无关文本、空段落、超限内容和不同 ASIN 仍然失败关闭。
- 不改变数据库结构、导入原子性、Provider、任务生命周期或前端提交次数。

## 测试与验收

1. RED：复现 `emoji + #1–#7 + 标准维度 + 括号说明` 被识别为零维。
2. GREEN：同格式完整报告归一化为七个维度并通过导入服务校验。
3. 回归：原有无编号、普通数字、keycap 数字和 Markdown 标题继续可用。
4. 反例：只有产品描述、无标准维度标题的任意文本仍被拒绝。
5. 使用用户本次原始报告做只读本地解析验收，预期 `filled=7`；不自动发起真实导入。

## 非目标

- 不引入 LLM 语义猜测。
- 不新增维度或 ASIN 特例。
- 不部署、不调用 Provider、不替用户点击导入。
