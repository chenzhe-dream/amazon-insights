# 历史同步失败折叠展示设计

## 目标

恢复项目页面时，已经终态失败的旧同步任务不再冒充当前运行故障占据主进度区；用户仍可查看原始失败原因。当前页面会话中新发生的失败继续完整展示，避免掩盖真实回归问题。

## 方案选择

采用 UI 归档方案：根据任务是“由 URL 恢复”还是“本次会话启动”区分历史与当前失败，不改 PostgreSQL、不新增归档接口、不删除任务文件。

未采用的方案：

- 数据库增加 `archived_at`：需要迁移、写接口和权限合同，超出本次展示修复。
- 自动清除 `syncJob` 并完全隐藏：会丢失诊断入口，也可能隐藏仍可安全续跑的任务。

## 交互合同

- 页面通过既有 `syncJob` 指针恢复到 `failed` 终态时，默认显示紧凑的“历史任务”摘要。
- 摘要显示固定生命周期标签和安全的既有任务文案，提供“查看详情”；展开后复用现有阶段明细与合法操作。
- 本次页面会话中新创建的任务若失败，仍立即完整显示，不自动折叠。
- `queued`、`running`、`completed`、`completed-with-gaps` 以及可恢复失败阶段的既有权限、刷新和去重合同保持不变。
- 折叠/展开只改变 React 展示状态，不发送 POST、不调用 Provider、不创建或修改 job/run/stage。

## 实现边界

- 在 `app/asin-sync-funnel.tsx` 内保存“恢复任务且尚未由本会话启动”的来源信息，并为恢复到的终态失败增加紧凑分支。
- 复用现有 `jobLifecycleLabel`、安全任务文案和按钮权限；不新增服务端字段。
- 样式只增加历史摘要所需的最小类，遵循现有卡片与按钮体系。

## 验收与测试

- RED：恢复一个既有 `failed` job 时，当前实现仍渲染完整进度和阶段列表。
- GREEN：该场景默认只显示一个历史摘要；点击“查看详情”后显示原有失败详情。
- 回归：同会话中新失败不折叠；恢复中的活动任务不折叠；折叠与展开均为零 POST；管理员/普通用户既有操作权限不变。
- 运行相关定向测试、changed-file lint 和一次 production build；最后进行一次限定独立复审。

## 部署约束

实现、测试和复审只在隔离 worktree 进行。部署前确认正式 active job/stage/attempt/run 为 0；部署不清理稳定 worktree 的业务 WIP，不触碰 PostgreSQL 数据。部署后由用户使用新的布罩灯 ASIN 发起一次真实测试。
