# 西柚缺凭据与变体缓存恢复

## 已确认范围

用户在根因说明后确认“先补齐再进行修复，随后我开始测试”。本轮只修复正式凭据传递、缺凭据覆盖有效变体缓存以及恢复此次受损的旧三款关联；不增加图表、演示模式或新缓存架构。

## 原因与选择

正式进程仅继承启动环境并加载仓库外 formal-stack.env；Windows User 中已有 XYDC_MCP_TOKEN，但正式配置和当前进程没有它。采集器读取缓存后在空 token 分支写入空家族，覆盖原父子关系，订单文件仍在但无法匹配。

采用显式私有配置加定点保护：优于依赖重开终端继承环境（不可持续验证），也优于放松订单身份校验（会串父体/子体数据）。不修改既有可选 Provider 的全局启动语义。

## 行为

- 凭据只在仓库外配置，原文件先备份；仅从本机现有 User 变量读取，不打印值，不提交 Git。
- 缺 token 时，复用结构有效、国家和输入 ASIN 精确匹配、采集时间非未来且具有子体证据的 ready/partial 缓存；返回 stale，保留原时间、父体、子体和质量状态，不写回覆盖该记录。force 也不能破坏已有证据。
- 无可复用缓存的 ASIN 仍明确返回 NOT_CONFIGURED，不伪造订单或子体；不发送 Provider 请求。
- 有 token 的缓存命中、刷新、请求限速/取消和订单缓存身份检查保持现状。
- 从已验证历史本地副本恢复受影响的 B07R56PTMS、B0F18D9B5V、B0CDW797MM 三个变体文件；先校验、备份和确认无活跃任务，不覆盖其他记录。若无可靠副本则停在恢复前说明，不能编造关系。
- 新三款 B01E6CX34C、B07Y4PJJR4、B07WFC14VR 的业务分析由用户发起；不提前跑完整采集。
