# 商品形态与关键词规则版收口设计

## 目标

本阶段让商品形态及价格带、类目关键词洞察的新建任务由来源采集和本地规则形成可读、可保存、可重放的报告。模型语义分析只作为后续扩展；本阶段不创建新模型任务。历史语义任务仍可读取。

## 形态链路

新建任务使用 `market-shape-price-flow/rules-v1`。采集及投影完成后，页面提示人工确认；保存修订只写入不可变统计版本，不因服务器存在模型配置而创建解释子任务。保存响应明确指出“本地规则任务未启用模型解释”。已有旧版语义任务维持原解释子任务行为。报告内保留原卡片与表格，语义位置显示未启用，不出现“等待模型”“待生成解释”的假等待。

## 关键词链路

新建任务使用 `market-keyword-flow/rules-v1`。固定词池与趋势来源生成 W5 和规则报告；W1–W4 没有经过人工分类或可靠语义结果时显示待分类/未知。页面保留原词表、五维区域、版本选择与来源审计，按 `ruleStatus` 呈现规则报告状态，`semanticStatus=skipped` 不显示为模型处理中。原版的“CPC 建议”控件标签保留，明细必须说明推荐竞价不是实际 CPC。

## 边界与验收

- 权威数字、缺失原因、证据与状态只来自已保存来源和 TypeScript 规则层；缺失不补零。
- 类目输入继续在各模块独立；本次不自动串联四模块。
- GET/刷新不创建新采集或模型调用；重放同一保存命令不产生额外修订或解释任务。
- 保留现有 UI 布局、历史入口、错误报告框；不发布或重启正式服务。
- 隔离数据库验证规则任务、修订与重放；页面测试验证成功、缺失与历史语义状态；运行类型检查、构建和相关测试。
