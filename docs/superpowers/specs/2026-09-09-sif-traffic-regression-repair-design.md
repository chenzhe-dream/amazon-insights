# SIF 流量格式与明细回归修复：设计修订

日期：2026-09-09。状态：用户已批准开始修复；本地实施中，未发布。

本文件承接 2026-09-04 的 `traffic-detail-projection` 设计，保留旧文档作为历史证据。本次修订只处理父 ASIN / 子体流量模块，不将前一轮 VOC 发布事务、排队耗时问题混入同一修复。

## 1. 已核实的原因

- `123c261`：2026-09-04 补全 SIF stage 投影中的广告、推荐、子体明细。
- `6280800`：同日兼容历史精简投影并规范数字精度。
- `3e4d594`：同日为动态快照补缓存明细。
- 2026-09-05 的正式整合从 `38c4c7d` 创建分支，挑选西柚功能增量时未包含上述修复。
- 诊断时正式 HEAD 为 `fff8c3e`，源码 HEAD 为 `6d278f8`；两处相关生产文件仍为修复前内容。实施时必须重新读取 HEAD，不将此记录当作永久基线。
- 当前 `app/lib/stage-output-view.ts` 将精简数据转换成带空明细数组的对象，再整体覆盖较完整的显示对象；页面直接显示未限制精度的比例。

这次属于集成遗漏。不能据此声称旧补丁此前已正式部署，也不能把问题归因于用户操作或要求用户反复重跑。

## 2. 方案比较与决定

| 方案 | 结果 | 决定 |
| --- | --- | --- |
| 三个旧提交直接整组搬回 | 修复主体可复用，但第三个提交默认按 ASIN 使用全局缓存，缺少任务与来源边界 | 不采用 |
| 只改小数或加宽 CSS | 数字看起来正常，但已获取的明细仍被丢弃，0 子体仍误导 | 不采用 |
| 选择性移植旧修复，补来源隔离、空态和最终集成回归 | 保留现有西柚功能，修复已知原因，同时防止旧数据冒充当前结果 | 采用 |

具体移植规则：`123c261` 的白名单投影是实现基础；`6280800` 的规范化和字段级合并可复用，但须修正缺字段归零；`3e4d594` 只复用适合当前版本的规范化，不恢复默认全局缓存注入。

## 3. 保留的业务与显示规则

1. 不改页面布局和业务口径，仍在当前“父 ASIN 流量结构 / 子体流量结构”模块呈现。
2. SIF 流量分显示整数和千分位，占比显示一位小数与 `%`；提示框与正文一致。流量分不改称订单量或精确访客数。
3. 原始浮点值保留在原始证据中；比例计算使用原值，最后才处理展示精度。上游 0–1 比例与已经转换为 0–100 的百分数必须分别处理，不能重复乘 100。
4. 保留 SP（常规）、SP（推荐）、SB（常规）、SBV。推荐来源沿用得分大于 0、份额至少 1%、降序取前 6 项的既有规则。
5. 子体按 ASIN 保持身份，渠道数组按原索引关联后才能排序。默认前 3 个、其余折叠的交互不变。
6. 条形宽度限制在 0–100%；不通过改分母或修改源值强凑 100%。

## 4. 数据优先级与缓存边界

新任务继续使用既有 `listingByAsin / monthlyByAsin` 外层协议。完整投影必须携带可显示的渠道、推荐和子体字段，不再只留下三个总量字段。

当前任务的完整 stage 明细优先于摘要 snapshot。摘要只能覆盖它真实具有的总量字段，不能生成空数组去覆盖已有明细。

历史精简数据只有在完整明细来源可核验时才能补齐：

- 服务端授权仍由现有项目 / run / job 读取接口负责；前端的匹配检查不是授权替代品。
- 授权组织、项目、run / job、站点、ASIN 和采集批次 / 产物关联必须一致。
- `TrafficSnapshotReadResponse` 正文本身没有 runId / organizationId；须使用已验证请求 owner 的上下文，不能虚构响应字段。
- 单独的 ASIN 相同、日期相近、总量相同，均不足以证明来源相同。
- 禁止在 `trafficDisplayFromSnapshot` 中默认读取编译时全局 `sifListingTrafficOverview` 来补当前 run。
- 在已选择当前任务的场景，无 dynamic snapshot、pending、404、401/403 时，也不得自动借用全局缓存冒充当前任务。切换任务 / 站点 / 登录状态后，旧响应不能重新写回。
- 当前 traffic owner 只绑定 run / 站点 / ASIN；修订必须补充会话身份、组织变化和登出开始时的立即失效。即使 run / 站点 / ASIN 未变，也要清空旧摘要和明细，阻止旧请求回填。这是需要增加的防护，不声称已经发生跨组织泄漏。
- 真正可核验的历史数据保留原始来源和采集时间，不能统一改为当前 snapshot 日期。

本次不新增“任意缓存都能复用”的跨任务缓存系统。无法建立同批关联时，不补明细、不伪造关联、不额外抓取；记录为未恢复项。

## 5. 缺失、空值与摘要必须分开

| 输入状态 | 处理 |
| --- | --- |
| 精简投影未包含某字段 | 保留同范围内可核验的已有字段；无证据则记为缺失 |
| 明确的数字 `0` | 保留有效零值 |
| 明确返回空数组 `[]` | 作为该字段的权威空结果，不用旧数组覆盖 |
| 日期明确为 `null` | 保留未提供状态，不用旧日期冒充 |
| 字段存在但畸形 | 标记不可用，不崩溃，不静默伪装为有效空结果 |
| 摘要给出 childCount，但无子体明细 | 显示“已识别 N 个子体，明细待补齐” |
| 连子体数量也未提供 | 显示“子体数据待补齐”，不显示“0 个子体” |
| 完整、可信的子体结果为空 | 才可以显示“0 个子体” |

摘要的“最大广告渠道”不能获得整个广告总分并被呈现成完整渠道分布。只有总量或最大渠道信息时保留摘要标签，明细区域说明待补齐。推荐总量也不能伪装成具体推荐来源。

6. 发布前记录最终提交、构建产物身份和数据指纹；发布后对照正式服务实际身份和浏览器结果。
