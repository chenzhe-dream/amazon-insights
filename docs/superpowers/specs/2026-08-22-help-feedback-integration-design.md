# 完整帮助与反馈中心移植设计

**日期：** 2026-08-22  
**状态：** 待用户复核书面规格  
**目标基线：** `3ddfcd3`（20 人并发候选版本）

## 目标

在不回退同步恢复、PostgreSQL 队列、资源许可、SellerSprite 额度和管理员并发控制的前提下，把已在旧隔离工作区完成的完整“帮助与反馈中心”移植到最新并发候选版本。完成后先在隔离端口通过自动化和浏览器验收，再执行真实 provider 阶梯验收；本阶段不修改或重启线上 `31900/31901/58258`。

## 选择的整合方式

采用“按能力移植”，不直接 merge 或 cherry-pick 旧反馈分支 HEAD。旧分支基于较早主线，直接合并会覆盖当前同步恢复与并发代码，并与现有 PostgreSQL `0011_sync_job_queue`、`0012_concurrency_control`、`0013_concurrency_admin_controls` 冲突。

执行窗口应以当前洁净候选 HEAD 为唯一基线，通过 RED 测试定义现有缺口，再参考旧实现重新接入所需组件、契约、仓储和路由。不得删除或重写当前并发提交。

## 用户界面

- 左侧栏底部、数据源状态上方显示“帮助与反馈”。
- 删除右下角重复的“反馈”按钮；保留“返回顶部”。
- 点击入口打开右侧抽屉，不离开当前分析页面。
- 所有登录用户看到“使用手册”“提交反馈”“我的反馈”。
- 仅规范化邮箱为 `admin@example.com` 且角色为 `admin` 的最高管理员看到“反馈管理”和未读角标。
- 草稿含标题、描述或附件时，关闭、遮罩和 Escape 都必须二次确认。

## 附件与反馈闭环

- 每条反馈最多 3 张图片；单张清理后最大 5 MiB。
- 只允许 PNG、JPEG、WebP；服务端根据真实内容识别、完整解码、限制像素并重新编码去除元数据。
- 浏览器支持文件选择、拖拽、剪贴板粘贴、缩略图预览、单张删除和明确的单文件错误。
- 使用浏览器生成 boundary 的 `multipart/form-data`，禁止 JSON Base64。
- 反馈、workflow、初始事件和附件必须在同一事务中原子写入；任一附件失败则整次请求不落库。
- “我的反馈”只读取当前用户自己的记录；附件通过单独鉴权流式端点读取。
- 最高管理员可查看本组织反馈、筛选状态、显式标记已读并变更 `new | processing | resolved | closed`；状态历史只追加且不可修改。

## 迁移与兼容

- 新反馈迁移统一使用全局下一个空闲编号 `0014_help_feedback_center.sql`。
- SQLite 与 PostgreSQL 都增加语义一致的 0014 迁移；SQLite 允许编号从 0010 跳到 0014，以保持跨后端同一能力使用同一编号。
- 绝不修改既有 `0001–0013` 内容或 checksum。
- 迁移新增 workflow、事件和附件表，并无损回填现有 `user_feedback` 为 `new`、未读、version 1 和确定性 created 事件。
- PostgreSQL 使用 `BYTEA`，SQLite 使用 `BLOB`；列表查询不得读取图片二进制。

## 代理、契约与权限

- `POST /v1/feedback` 仅此路由允许受限 multipart；其他代理路由继续保持现有 JSON 和大小边界。
- 附件 GET 仅允许受限二进制流；响应设置真实 Content-Type、nosniff、Content-Length、安全 inline 文件名和私有短缓存。
- 所有 JSON 合同保持严格 schema；错误不得包含 SQL、数据库 URL、凭据、请求头、图片字节或内部堆栈。
- actor、organization 和管理权限只从认证 principal 推导，不能信任浏览器字段。
- 普通管理员没有组织反馈管理权限，与 member 一样只能查看自己的反馈。

## 不在本阶段实施

- 不做管理员回复、聊天、邮件、钉钉通知或在线编辑手册。
- 不接 NAS、R2、S3，不改当前 PostgreSQL 架构以外的存储部署。
- 不改变并发策略、连接器限流、SellerSprite 额度或真实 provider 阶梯验收设计。
- 不部署、不 push，不操作线上真实反馈或附件数据。

## 验收门禁

1. RED 证明最新候选仍缺少左侧入口、附件选择/拖放/粘贴、multipart 代理和附件读取。
2. 迁移覆盖 SQLite/PostgreSQL fresh、reopen、历史回填、checksum 和事务回滚。
3. 权限覆盖未认证、member、普通 admin、最高 admin、跨用户和跨组织不可见。
4. 图片覆盖超 3 张、超 5 MiB、伪格式、损坏图、超大像素、去元数据和重启可读。
5. 真实同源代理测试证明 multipart 提交成功、附件流成功，不能用 route interception 掩盖代理问题。
6. 浏览器验收证明左下角入口、右下角重复按钮移除、四个标签、三种图片输入、预览/删除、我的反馈、管理筛选、未读、状态历史和丢弃确认。
7. 运行直接受影响的同步、并发、认证和代理回归，确保反馈移植没有回退当前 `3ddfcd3` 能力。
8. 一次 fresh build、`git diff --check`、严格 OpenSpec/迁移检查通过后，由独立 reviewer 限定复审本次移植 diff；Critical/Important 为 0 才允许进入真实 provider 阶梯验收。

## 回退

反馈移植保持为独立提交序列。验收失败时只停止后续验收并保留隔离工作区证据，不修改线上服务、不删除运行数据、不恢复右下角旧反馈作为正式方案。修复只在当前移植范围内继续。
