## 5. 采集修复的范围与技术边界

已确认的修复范围来自观察到的限流和断点恢复问题，不承诺供应商永不限流：

- 批次内复用连接，对实际 HTTP 发出节流；相同主机、同凭证的任务共享冷却，不能换 ASIN 绕过等待。
- 尊重合法 Retry-After；缺失指示采用有界退避。超时或结果未知不自动重复收费调用；认证、额度不足和反复限流停止继续碰撞。
- 成功且身份校验通过的子体及时保存，保留真实时间；失败补采不覆盖原先完整数据，不把缺失当零。
- 进度需绑定已鉴权项目与实际任务代次；取消后停止后续请求；读取进度不触发新采集。
- 开发、正式数据根及工作树继续隔离；不得以协调限流为由共享整个 runtimeRoot 或修改其他窗口代码。

新 B 计划为 `2026-09-08-xydc-collection-resilience-v2.md`，分为采集恢复和任务进度两项，任务正文各自锁定本版本边界。已核查：现有 canonical traffic 的 analysis run 可先结束而 sync job 仍运行，因此不能把任意 run 终态当作西柚取消。进度绑定固定job/owner/lease generation和有效租约，显式run cancelled作为否决；旁路进度文件不是权限来源。OpenSpec窗口已只读确认无正在写入的冲突，可信lease/abort链、其他Provider与发布合同、鉴权读取和前端过期响应拦截等窄边界均纳入B计划；这不代表实现已验收或获准发布。无数据库迁移或通用任务架构重写。

2. 派发前核对：每份独立任务简报自身必须包含范围版本、允许的 A/B 编号、K1 保留项、D1/D2 排除项、文件归属及正式环境禁改项；不能只在计划顶部写限制，因为任务提取可能只抽取 Task 正文。
3. 一任务一映射：新源文件、功能、测试与共享入口改动须能对应已批准编号。新建月度投影或月度交互测试不能借“完善测试”进入本轮；运行现有月度回归用于证明未破坏 K1 是允许的。
4. 变更先行：用户说“先不做”“取消”“换一种”时，立即停掉受影响任务，同步更新范围、计划、简报和当前进度，旧 Task 明确失效。新增需求先说明影响、获得对应确认，再改任务。
5. 提交前审查：检查实际 diff 与批准编号，不只看测试是否通过；发现月度新增或其他越界改动，先隔离并纠正，不提交或发布。
6. 并行保护：同一源代码段只设一个写入者；修改共享入口前核对 OpenSpec 窗口的边界，不覆盖其改动。发布另走明确授权。
7. 交付说明：分别列本轮已做、未做、测试覆盖和遗留问题，不把设计、模拟验证或计划提交说成实现完成。
