# 西柚订单悬浮明细与采集稳定性设计

日期：2026-09-08

状态：用户已同意方案方向；书面设计待用户审核。本轮只提交设计，不实施功能、不发布正式服务。

## 1. 已确认的范围与取舍

用户希望在月份柱状图悬浮时，像西柚页面一样查看具体订单数及份额，并减少详情窗口下方表格常驻占用；同时修复本次真实采集暴露的限流与恢复问题。

采用的方案：**月度悬浮明细 + 年度份额悬浮 + 详情年度表默认折叠**。手机点击、键盘访问必须可用。

不选“所有月度、年度列塞进一个悬浮框”：周期容易混淆，10 个子体时内容过宽。不新增饼图或环形图：本版年度份额条已经承担占比比较，重复图形不增加必要信息。卡片现有前三个子体预览表保留；默认折叠的只是详情窗口中的“全部子体 · 年度份额”表。

本设计分为两个独立交付单元：A 为只读展示交互，B 为服务端采集与状态反馈。两者共享现有订单合同，但不互相触发查询。先分别验证，再联合验收；不扩展为通用图表平台或全供应商任务系统重构。

本设计补充 [原年度订单设计](2026-09-08-xydc-parent-orders-12m-design.md)。数据口径、授权及正式环境保护继续有效；本设计第 5 节明确替代原设计第 5 节末尾的“仅业务调用间隔 2 秒、Retry-After 不超过 30 秒才重试”策略。

## 2. 真实问题与非产品问题

当前功能代码基线为 `8f140346d4caa4e03e3a5dd761dfc751d7720f2f`。本地真实验收覆盖 B07R56PTMS、B0F18D9B5V、B0CDW797MM，共 21 个已知子体。

- 第一轮 22 次业务尝试中出现 6 次 RATE_LIMITED，剩余 5 个子体未齐；第二轮仅补采这 5 个，全部成功。不能把“最终补齐”表述为“首轮批量采集没有问题”。
- 当前每个业务调用新建、连接、关闭 MCP Client。实际诊断中一个业务调用产生 initialize、initialized、GET stream、tools/call 共 4 个 HTTP 请求。2 秒的业务开始间隔不等于底层请求已限速。
- 当前仅在 Retry-After 已解析且不超过 30 秒时重试一次；缺失或更长的等待指示被丢弃，RATE_LIMITED 不会阻止接着查询下一个子体。这个本地恢复策略缺口已经从代码确认；供应商究竟怎样计数限流仍不能仅凭现象断言。
- 已成功子体的有效缓存复用、失败项补采、错误数据不补零已在真实测试中成立，要保留并加固，而不是推倒重写。
- 验收辅助页的静态标记 hydration 报错已修正，属于辅助页初始化方式；后台点击屏外按钮的问题属于自动化操作。二者应固化到验收工具规范，不据此改动无关正式产品代码。

本轮不调用收费接口、不修改已有真实数据。后续真实回归先复用已取得快照，必须重新联网的部分限定为当前三个灯的已知子体，并单独报告请求量与是否消耗积分。

## 3. 展示与数据口径

### 3.1 月份悬浮信息卡

每一个月份的整个柱图区都能触发，不要求用户准确指向某一小色块；空柱或未披露月份也有同等入口。

信息卡依次展示：

1. `YYYY-MM · 月度订单明细`。
2. `当月已披露订单汇总（全部 N 个子体）：…` 与覆盖状态。
3. 子体列表：颜色标识、变体名称、ASIN、当月订单量、当月占比。
4. 数据口径及缺失／未披露说明，旧快照另标“缓存数据”和采集时间。

列出完整当前子体集合，不将前三名或 Top 50 当成全量。顺序按当月正值降序、未披露值其次、缺失值最后，同值按 ASIN 排序。列表超出可视高度时只在信息卡内滚动，不裁掉其余子体，也不新增分页查询。

月度示例（LEPOWER 实际 2025-12 快照）：汇总 650+；B07R56PTMS 为 500+、76.92%，B0834KGXN1 为 100+、15.38%，B0831DV4D9 为 50+、7.69%；B0831FMFVW 显示“未披露”，占比显示“—”。不能照抄供应商截图，把无阈值说明的原始 0 一律变成 `<50` 或真实 0.00%。

月度占比分母是该月全部子体已披露值之和，与年度分母分离。比例保留两位小数，舍入后之和可能为 99.99% 或 100.01%，不人为修改某一子体凑到 100%。不在月度列表里暗放年度数字；完整年度信息由年度份额入口及折叠表承担。

| 月度数据状态 | 汇总与占比 | 明细 |
| --- | --- | --- |
| 全部子体该月有响应，且有正值 | 显示已披露汇总与正值子体占比 | 原始 0 显示未披露、占比 — |
| 全部有响应但均为原始 0 | 显示暂无可披露订单数据，不绘制伪份额 | 所有子体显示未披露 |
| 任一子体缺月、请求失败或身份不符 | 汇总 —，标明数据不完整；所有当月占比 — | 已验证的可用值仍展示，缺失项明确区分 |

月份来自供应商返回的 YYYY-MM 和本批次固定 UTC 窗口，不新增“美国时间”断言，不对月标签做浏览器时区换算。年度不完整不必隐藏某一个完整月份的真实月度分布，但绝不由此计算完整年度份额。

### 3.2 年度份额悬浮信息卡

卡片的年度份额条每个正值子体色块，以及对应图例，展示该子体的：变体名称、ASIN、固定 12 个月起止、年度已披露订单合计、年度份额、缺失／未披露月份数。

使用当前年度 summary 的值，不重新计算另一套总量，不以颜色或排序下标寻找数据。色块、图例、月度堆叠和表格均按 ASIN 对齐。现有 8 色会在更多子体时循环，始终同时显示 ASIN 与属性文本，不能声称颜色唯一标识子体。零宽度或非常小的色块可通过图例进入，不能成为唯一访问入口。年度不完整时没有份额条，图例和完整表仍可呈现已有数据及“—”，不把部分数值伪装成年度总量。

### 3.3 年度表折叠

详情窗口初次打开时，保留“全部子体 · 年度份额”标题、子体数量以及“展开年度明细”按钮；表格和排序控件一同折叠。展开后保留现有年度值、份额、缺失／未披露月份、ASIN 普通跳转和两种排序。

同一详情窗口展开后，刷新相同身份数据保留展开状态；关闭窗口、切换父体或统计窗口后恢复折叠。不得因排序把悬浮内容绑定到别的 ASIN。折叠内容条件渲染，展开按钮关联 aria-expanded/aria-controls；现有焦点收集只检查控件自身 hidden，不能仅隐藏祖先就认为排序和链接已退出 Tab 循环。逐月无障碍数据表继续保留，不随年度表折叠丢失。

## 4. 鼠标、触屏、键盘与窗口生命周期

- 视觉上采用白底、浅边框、轻阴影的信息卡；正文不小于 12px，ASIN 和数值不被省略。保留现有整体配色，本版不新增独立主题。
- 鼠标进入触发区即展示；离开触发区和信息卡后关闭，短暂跨越两者间距不闪退。信息卡可被鼠标进入并滚动。
- 点击／触屏点按可固定展开；点击其他触发区切换内容，点击空白或关闭按钮收起。手机按可视宽度展示，内容不挤出屏幕，触摸不会意外触发 Amazon 跳转。
- 每月触发区和年度图例有可聚焦入口，支持 Enter/Space 展开及关闭。图表装饰本身可 aria-hidden，但可操作入口不能放在 aria-hidden 子树中。
- 信息卡是非模态、具备可读标题的受控区域，触发按钮用 aria-expanded/aria-controls 关联；不嵌套第二个模态 dialog，也不将含关闭控件的区域冒充纯文本 tooltip。固定后可进入明细区域，关闭后回到有效触发入口。
- 一次只显示一个活动信息卡。详情弹窗开启时清除外部年度信息卡；弹窗内信息卡必须归属弹窗 DOM／焦点范围，避免 portal 到 body 后被外层焦点约束排除。
- Escape 先关闭当前信息卡并阻止本次按键继续关闭外层详情；没有信息卡时 Escape 才关闭详情。显式关闭后，即使触发入口仍处于 hover/focus，也不得立即重开；离开后重新进入或再次点击才可打开。关闭整个详情、切换国家／父体／窗口、授权范围变动、数据身份失效时清理悬浮状态和定时器。
- 定位以视口边界为准，靠右翻转、靠下上移；窗口调整和容器滚动时重算位置。不能因父容器 overflow 截断内容。
- 展示层只读已经授权取得的快照；hover、focus、tap、展开表格和排序均不调用西柚，不加载浏览器控制，不创建浏览器分组。

## 5. 采集稳定性设计

### 5.1 有范围的连接复用

为一次年度订单采集创建显式的服务端会话作用域，批次内子体共用连接。变体关系和商品信息保留现有单次调用入口及测试注入兼容，但三个允许工具都必须经过同一网络保护，不在本版重构变体采集算法。全缓存命中时不创建网络连接。

会话按规范化 endpoint 和凭证隔离，不能让不同 token 共享 Client、Authorization，或把一个在途请求响应交给另一个凭证的会话。已经校验和授权的商品业务缓存仍按现有数据身份规则复用，不新增账号级业务缓存分区。生命周期由批次级 controller 管理；每次工具调用另有独立取消／超时控制，不能把第一个子体的 signal 绑定为整条连接 signal。批次正常结束、异常、取消和连接失败都必须释放资源，连接未完成也不能泄漏 transport。

已安装 SDK 的 transport 会用自己的 signal 覆盖 requestInit.signal；工具请求 Promise 取消不证明物理 HTTP 已停止。设计采用串行工具调用：实际网络超时或取消时先关闭当前作用域的受影响连接、停止底层请求，再按原因决定是否允许后续新工作重建连接。不能把结果未知的原查询自动重放，也不影响其他批次的会话。

当前 SDK 的请求 abort 监听会发送 notifications/cancelled；因此成功结束时必须清除自己持有的计时器和监听，不再无条件 controller.abort()，也不留下完成后继续触发的 AbortSignal.timeout。会话退出时先断开 transport 再清理请求控制器，确保成功后的延迟取消、预算到期后的取消通知均不会绕过网络保护。

只在本地模拟 MCP 服务验证当前 SDK 的连续工具调用、取消和连接恢复语义后接入复用。SDK 隐式重连／重试保持关闭，避免与业务重试叠加。会话损坏时清理；后续工作可在预算内重新连接，但对已发出、结果未知的收费 tools/call 不自动重放，保留明确缺失状态。

### 5.2 真实 HTTP 节流与共享冷却

节流放在西柚 transport 的实际 fetch 边界，覆盖握手、通知、GET stream、tools/call 及重连请求；不能只给业务函数加 sleep。设计默认相邻实际请求发出至少间隔 2 秒，这是本系统保守默认值，不声称是供应商保证的安全限额。

同一主机使用专门的网络协调目录（coordinationRoot），规范化 endpoint + 凭证指纹共同标识一套限速与 cooldown 状态，覆盖同凭证的多个任务和进程。指纹只用于服务端内部键，不写原始 token、Authorization 或完整 provider 响应；不同凭证状态不得串用。

选择较窄的同凭证批次租约：复用已有异步进程锁，一个年度批次持有租约期间，其他相同凭证的西柚调用可取消地排队；现有单次工具入口持有单次调用租约，不能绕过批次保护。租约内的调用复用已有所有权，不嵌套申请自身锁；获得租约后重新读取缓存，避免使用排队前的旧状态重复采集。

订单作用域的租约等待消耗其 300 秒总预算；兼容单次调用入口继续受其原有 15 秒总期限（含租约排队）约束。不存在没有截止时间的锁等待；兼容调用超时也不得绕过协调器发送。

持有者逐个实际 HTTP 请求节流，并原子保存下一次允许发出时间及 cooldownUntil；下一位持有者继承这些状态。等待可以取消，锁所有者使用唯一 nonce 和进程身份；异常退出按已有机制恢复，不抢占仍存活的持有者，不无条件删除其他任务的锁。状态不可安全读取或锁不能取得时停止当前补充请求并报告可恢复错误，不绕过节流继续发送。该方案不再额外叠加子体查询级进程锁。

开发和正式进程保留各自的 runtimeRoot、dataRoot 和任务文件隔离，仅用服务端配置 `XYDC_COORDINATION_ROOT` 指向同一个专用绝对路径；不能为了节流去修改整个 AGENT_RUNTIME_ROOT。生产联网入口必须验证该协调路径已配置可用，测试显式注入临时目录。不同主机、不同协调根或未接入本客户端的工具不会自动共享限速；未来服务器与开发机共用同一凭证时应使用独立凭证或禁止同时采集。本版不引入 Redis、跨服务器锁或跨账号配额猜测。配置接入属于后续实施步骤，本轮不改环境文件。

### 5.3 429、超时和失败处理

- 所有可识别 429 都先设置该凭证的共享冷却，不能通过换 ASIN 继续请求。
- 接受合法 Retry-After 秒数或 HTTP 日期。短等待按指示执行；超过当前阶段剩余预算的等待不截短后提前重试，保存可用结果并以“限流待补采”结束。本次不再把 31 秒这样的合法值直接丢掉。
- 缺失或无法解析 Retry-After 时，首次采用 30 秒冷却；同一批次再次出现无有效指示的 429 时采用 60 秒冷却。都是本地退避策略，不冒充供应商指示。明确等待时长超过实现可安全表示范围时，不自动重试且不得退回更短默认值。
- 每个子体最多两次业务尝试（首次 + 一次 429 后重试）。重试仍被限流时停止本轮剩余订单调用、保存结果并提示待补采，不给每个剩余子体再撞一次限流。
- 认证无效、积分不足立即停止本轮后续西柚请求并区分原因；404、格式／身份不符只标记对应数据失败；已发出请求超时且结果未知时不自动重复收费调用。
- 订单阶段总预算继续为 300 秒，包含排队、锁等待、节流、冷却、握手、请求和重试；不足以安全开始下一次请求时保存部分结果并结束。POST 从实际发出到完整 JSON／匹配 MCP 结果上限 15 秒；GET SSE 只限制建立响应头的等待为 15 秒，不每 15 秒杀掉正常长连接。节流排队不误算成网络超时，但始终受总预算与外层取消约束。
- 取消、预算耗尽或任务终止后不再发出新请求；清理本作用域 timers、listeners、Client 和 transport，不影响其他任务会话。

### 5.4 成功结果保存与补采

单批次内的网络请求去重键包含国家、子 ASIN 和固定窗口；持久化检查点额外记录并验证父体及完整子体集合身份，只有关系身份相同时才能跨批次复用。父体快照仍验证国家、父体、完整子体集合、版本和窗口。

有效完整子体优先复用。每次成功响应经校验后建立可恢复检查点，不等整个 21 子体批次结束才保留成果。相同凭证、相同数据根下的并发任务在获得批次租约后重新读检查点，第二个任务复用已完成结果，不重复发出同一收费查询。不同凭证或隔离测试数据根不承诺跨任务收费去重；写入仍原子化并校验身份，不能让并发旧结果回写覆盖更新时间更晚的有效检查点。

检查点与公开父体结果分离：失败刷新不得把原先完整同身份快照覆盖成不完整数据；刷新成功的新子体也不能因回退旧父体快照而丢掉。新鲜结果齐全后原子发布；部分首次结果允许展示但必须标记不完整。旧快照保留其真实采集时间和失败／缓存标记，不刷新时间假装新采集。

缓存有效期及身份验证沿用现有规则。跨月、不同国家、父体集合变化不把旧值移植到新身份；原始零、缺月与失败继续严格区分。显式 force 是用户发起的刷新，不由页面交互、自动重试或验收工具偷偷启用。

## 6. 可见进度与接入边界

进度是本次采集的事实，不按经过时间伪造百分比。显示位置在西柚订单模块，不改 VOC 进度，不改变核心同步成功条件。

展示状态为：等待开始／排队、采集中、限流等待、已完成、部分完成待补采、失败、已取消。示例：`已就绪 16/21 个子体 · 限流等待，约 30 秒后重试`。就绪数只计算 12 个月合法响应的唯一子体，包含已验证缓存；另列缓存复用数和未完成数。原始零依然计为有响应，不伪装为有真实销量。

后端产生有版本的进度记录，包含 task/run 身份、项目授权范围、国家、窗口、父体集合身份、计数、状态、有限枚举原因、updatedAt 和可选 retryAt。只在后端写入事实更新；等待期间保活，客户端可以按 retryAt 倒计时，但到零不自行认定采集成功。

通过现有已鉴权 runtime 读取链路增加可选订单进度成员，旧响应默认无进度。只投影当前项目、当前请求 ASIN 对应范围；不能返回别的项目的子体列表或累计计数。没有可信任务关联的独立 CLI 执行仅保留后台诊断，不凭相同 ASIN 假装是当前用户任务。

页面处于活动采集期间时复用一个项目级读取循环，最多每 5 秒读取一次，不由每个卡片各自轮询；没有活动任务、切换项目、页面隐藏或组件卸载时停止／取消。新响应必须校验请求身份，迟到的旧项目响应不能覆盖当前页面。GET 仅读状态和缓存，永不重启采集。

由西柚子进程直接原子写入独立进度 sidecar，而非仅输出 stdout：现有命令包装使用 spawnSync，父进程等子进程退出后才读取 stdout，不能提供实时状态。本版不为进度重写通用命令执行器。启动方显式传入任务关联，子进程验证关联后每 15 秒保活、在状态变化时立即更新。

不能依赖阻塞中的父进程转发取消：子进程每 1 秒核验所属 job/run 的终止、取消与运行代次，排队或冷却中也持续核验；退出信号同样接入批次取消。每条进度按 run/generation 隔离，写入前验证仍是当前代次，旧子进程的迟到心跳或完成事件不能覆盖新运行。发现所属任务已取消、终止或代次失效时真正停止收费请求并释放资源；仅在页面标“中断”不足以满足取消要求。任务状态不可安全读取时停止新请求、保留检查点并显示可恢复原因。

活动记录超过 45 秒未更新、工作进程终止或所属任务已终止时，读取侧显示“状态已中断／待确认”，保留数据，不永久转圈或擅自标 100%。即使预计冷却较长也继续保活。每条记录限制 64 KiB，保存每个任务的最新进度而非逐次事件；终态记录保留 24 小时，同环境最多保留最近 200 条终态记录。只清理本模块符合合同且已终态的记录，不清理活跃记录或其他任务文件。默认值在实施计划中落实为可测试常量。

最小接入面为：西柚补充命令获得现有 job/run/project 关联并转发取消；订单采集器写独立进度；runtime 授权读取与模块呈现读取。不得为此重写 OpenSpec 窗口正在维护的核心任务发布、全局进度或重启保护。若必须改共享入口，先核对并行差异并协调同一段代码的单一写入者。
