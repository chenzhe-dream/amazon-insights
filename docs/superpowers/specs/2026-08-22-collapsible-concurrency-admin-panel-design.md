# 可收缩并发与额度管理面板设计

日期：2026-08-22
状态：用户已确认设计方向，等待书面规格复核

## 1. 背景与问题

并发与卖家精灵额度管理功能已经上线，但当前管理面板没有完成视觉实现。真实页面表现为标题、指标和操作控件连续堆叠，缺少卡片、间距和清晰的信息层级。

只读诊断确认这不是整站样式加载失败，而是面板引用了未定义的指标布局样式，并在操作区嵌套复用了带外边距和自动对齐规则的通用布局类。结果是：

- 四个状态指标没有独立卡片；
- 面板主体缺少合理内边距；
- 策略选择、按钮和额度输入相互挤压；
- “状态正常”与“凭证未配置”的原始英文原因同时出现，语义冲突；
- 面板长期占据首页较大纵向空间。

## 2. 目标与非目标

### 2.1 目标

- 默认用紧凑状态条快速展示策略、队列、额度和连接状态。
- 最高管理员可从紧凑状态条展开完整管理仪表卡，再收回紧凑状态。
- 完整状态使用现有页面的浅色卡片、蓝色主按钮和中文管理文案。
- 管理操作与只读指标清楚分层。
- 桌面、中等宽度和窄屏均保持可读、可操作。
- 锁定样式和权限表现，避免再次出现“功能存在但没有样式”的回归。

### 2.2 非目标

- 不修改 PostgreSQL 队列、并发策略、配额算法或连接器熔断逻辑。
- 不新增或修改 Agent/Web API。
- 不改变最高管理员、普通管理员和成员的权限边界。
- 不增加本地持久化；刷新页面后恢复默认紧凑状态。
- 不重新设计侧边栏、首页或其他业务卡片。
- 不触发真实卖家精灵额度刷新或任何 provider 任务。

## 3. 已选方案

采用“默认 A 紧凑状态条，按需展开 B 管理仪表卡”的单组件双状态方案。

没有选择固定完整仪表卡，因为它会持续占据首页空间；没有选择侧边抽屉，因为它需要新增入口、遮罩和开合导航，改动更大且不利于快速扫视。

## 4. 交互与状态

### 4.1 默认紧凑状态

管理员进入或刷新页面后，面板默认收缩。紧凑状态包含：

- 面板标题“并发与额度”；
- 当前策略档位；
- 排队、运行和暂停数量；
- 卖家精灵总额度或“总额度未知”；
- 连接器业务状态；
- “展开管理”按钮。

紧凑状态只展示摘要，不显示策略切换、暂停、熔断重置或额度配置控件。

### 4.2 展开管理状态

点击“展开管理”后，在原位置展开完整仪表卡：

1. 顶部为标题、权限说明和当前策略徽标；
2. 中部为四张指标卡：策略、队列、卖家精灵额度、连接状态；
3. 指标卡下方显示额度更新时间或安全提示；
4. 底部为独立管理操作区；
5. 右上或底部提供“收起”按钮，返回紧凑状态。

展开与收起只改变当前页面内的显示状态，不请求服务端、不写浏览器存储，也不改变任何业务配置。

### 4.3 权限

- 成员：不渲染面板，保持现有行为。
- 普通管理员：可展开查看完整只读指标；不渲染变更策略、额度或熔断的控件。
- 最高管理员：展开后显示全部已存在的管理操作。

## 5. 视觉结构

### 5.1 完整仪表卡

- 面板沿用现有白色卡片、细边框、12px 圆角和轻阴影。
- 内容使用统一的 18–20px 内边距。
- 指标卡使用浅灰白背景、细边框和清晰的“标签—主值—说明”层级。
- 操作区使用独立顶部边框和浅色背景，与只读数据区分离。
- 策略选择与“切换策略”组成一组；额度输入与“保存”组成一组。
- 暂停和解除熔断保持次级操作外观，不伪装为主要提交按钮。

### 5.2 响应式

- 宽桌面：四张指标卡同排。
- 中等宽度：两列两行。
- 窄屏：单列；操作控件换行，输入框和对应按钮保持同组。
- 不允许控件水平溢出页面或压缩到无法识别。

## 6. 状态语义与文案

连接状态必须根据现有安全投影显示一致的中文业务文案：

- 已配置且可用：绿色“正常”。
- 未配置：黄色“未配置”，说明“尚未配置卖家精灵凭证”。
- 手动暂停或熔断：黄色或红色“已暂停”，显示安全的现有原因。
- 暂时不可用：黄色“暂不可用”。

不得在“未配置”时同时显示“正常”，也不得把原始英文配置错误直接暴露为主要界面文案。仍须保留现有的密钥、数据库 URL、Cookie、租约和上游原始响应隐藏约束。

## 7. 错误与进行中状态

- 初次读取时显示有边界的加载状态，不让页面结构塌陷。
- 读取失败时显示“并发与额度状态暂不可用”，面板仍可收起。
- 管理操作进行中时保留现有单操作互斥，禁用相关控件并显示进行中文案。
- 更新失败只显示安全的中文失败提示，不展示服务端内部错误。
- 未配置凭证时，手动刷新继续服从现有服务端校验；本设计不绕过校验或创建真实调用。

## 8. 可访问性

- 面板继续使用命名区域“并发与额度”。
- 展开按钮使用 `aria-expanded` 和与完整内容关联的 `aria-controls`。
- 状态不能只依赖颜色，必须同时显示文字。
- 表单控件保留可读标签；按钮焦点样式与现有设计系统一致。
- 收起后焦点返回展开按钮，避免键盘用户丢失位置。

## 9. 验收与回归验证

### 9.1 组件行为

- 成员不渲染面板。
- 普通管理员默认看到紧凑摘要，可展开完整只读指标，但看不到变更控件。
- 最高管理员默认看到紧凑摘要；展开后看到全部现有管理控件；收起后控件消失。
- 展开、收起和页面刷新均不触发策略修改、额度刷新或其他 POST/PUT。
- 页面刷新后重新回到紧凑状态。

### 9.2 样式合同

- 面板、指标网格、指标卡、操作区和紧凑状态均有专用样式选择器。
- 宽桌面为四列，中等宽度为两列，窄屏为一列。
- 操作组不会继承通用构建器布局的自动外边距或主按钮自动推右规则。
- 在正式页面宽度下，面板无裸文本堆叠、无水平溢出、无控件重叠。

### 9.3 业务不回归

- 现有并发/额度组件测试继续通过。
- 最高管理员与普通管理员权限合同不变。
- 现有读取和变更 API 调用数量不增加。
- 一次生产构建通过。
- 不执行真实 provider、同步任务或额度刷新。

## 10. 发布边界

- 在隔离候选工作树实现并提交。
- 实现侧只运行本面板相关定向测试和一次构建。
- 只允许一次限定独立复审，范围为本设计、该次新增 diff 和直接 UI/权限阻断。
- 未经用户再次批准，不 push、不部署、不重启或触碰当前 31900/31901/58258 实例。
