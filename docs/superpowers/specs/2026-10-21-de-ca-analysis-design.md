Production 31900/31901 and the existing 32900/32901 candidate remain untouched. This work is based on formal commit 7efbc72a, in an isolated worktree, exposed on 33900/33901 with a separate PostgreSQL database and data/runtime roots.

Extend the existing project, collection, snapshot, and analysis pipeline rather than maintaining a second pipeline. A shared explicit project marketplace contract supports US, UK, DE, CA. Existing market/organization/project/ASIN provenance, request identity, retries, and immutable report ownership remain mandatory. Same-ASIN US caches must never satisfy DE or CA readiness.

Preserve the existing US-only legacy/manual Alexa vault contract; do not relabel review evidence as manual Alexa. Missing keywords, unsupported provider operations, incomplete source coverage, and empty responses retain their reasons. Never synthesize data, reduce the requested cohort to create success, or reuse another site's values.

If an external source genuinely blocks completeness, continue all independent work and report the precise remaining gate.

Live diagnosis addendum: same-day date-only review captures must use their integrity-checked scoped publication time, while actual future record days remain invalid. A provider child-sales value of -1 means unavailable, and must neither become zero nor turn all sibling ASINs into connector failures.

The real German model response exposed one transport format defect: an otherwise complete JSON object followed by one extra closing object brace. An explicit candidate-only relay compatibility setting may remove exactly that one trailing character only when the remaining prefix parses as a complete non-null JSON object. The default remains strict. Responses transport, multiple extra characters, prose, arrays, truncated JSON and arbitrary syntax repairs stay rejected. The unchanged full schema and evidence validation decide publication. Content-free normalization metadata and hashes make this operation auditable; the private original capture remains outside Git and ordinary logs. A successful parse alone is insufficient for live acceptance.

Further live responses also exposed internal malformed JSON and unknown theme references. The candidate explicitly selects relay `json_object` wire mode only after a minimal real capability probe; the default remains `json_schema`. The exact schema is still supplied in the prompt, and local schema/evidence validation remains mandatory. Provider audit names distinguish JSON-object mode. Theme references in the compact response schema are restricted to the actual frozen `(dimension, themeKey)` pairs; no output references are guessed or silently substituted. Schema construction must be deterministic across preparation, execution and repair. Official request-contract reference: https://developers.openai.com/api/docs/guides/structured-outputs . The relay probe establishes parameter acceptance for that service, not strict schema enforcement.

Product-definition model failures must remain `model-output`, rather than becoming generic infrastructure failures. Its runner uses the same safe validation logger. Frozen VOC/keyword evidence IDs, theme keys and keyword group IDs also constrain the product wire schema, while the original full validator remains authoritative. Empty source sets must never create synthetic placeholder references. Validate legal full output, unknown-reference rejection, stable schema digest and identical repair schema before another real product-stage run.
