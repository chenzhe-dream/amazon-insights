# 同步就绪度与 VOC 导入反馈设计

## 目标

修复两个会误导运营人员的展示问题：

1. Alexa VOC 导入返回结构化错误时，页面不得显示 `[object Object]`。
2. 同步就绪度应反映每个 ASIN 的每个自动模块，而不是要求某模块的全部 ASIN 都就绪后才计分。

## 已选方案

### 自动模块就绪度

仅统计 `SYNC_STAGE_TEMPLATE` 中 `kind === "auto"` 的模块。每个 `ASIN × 自动模块` 为一个计分单元：

- 分母：`ASIN 数 × 自动模块数`。
- 分子：状态为 `done` 的计分单元数。
- 百分比：`Math.round(分子 / 分母 × 100)`；无 ASIN 时为 0%。
- 页面同时显示明确计数，例如 `自动模块就绪 21/33（64%）`。
- 人工 Alexa VOC 不进入自动模块分母，继续单独显示 `待录入 VOC 3 个`。

当前三 ASIN 的真实状态是 33 个自动计分单元中 21 个就绪，因此显示 64%，不再显示按整列计算得到的 36%。

### VOC 导入错误

前端使用有界错误投影读取结构化响应：优先读取安全字符串消息，不对对象执行 `String()`。HTTP 422 显示固定中文提示：

> 导入失败：请确认报告包含当前 ASIN，并至少包含 3 个标准维度标题。

未知响应使用通用“导入失败”，不得显示响应体、内部堆栈或敏感字段。

## 备选方案与取舍

- 保留“全部 ASIN 都就绪才算模块完成”：实现不变，但会把已有大量数据的页面显示为 36%，继续误导。
- 按任务生命周期百分比：适合运行中进度，不代表终态数据完整性，不能用于当前“就绪度”。
- 采用 ASIN × 模块矩阵（本方案）：能准确表达部分成功，并与页面逐 ASIN 的缺口一致。

## 修改边界

- 在同步展示 helper 中增加纯函数，集中计算计数和百分比。
- 在 VOC 导入面板或独立 helper 中增加安全错误消息投影。
- 不改变 Provider、同步任务、数据库、VOC 入库合同或人工 VOC 的完成门禁。

## 测试

- RED：三 ASIN、十一自动模块、二十一个就绪单元时，旧逻辑返回 36%，新合同要求 `21/33/64%`。
- 覆盖空 ASIN、全部就绪、部分就绪，以及人工 VOC 不计入分母。
- RED：结构化 `{ error: { message: ... } }` 不得渲染为 `[object Object]`；422 必须返回固定中文提示。
- 运行受影响单测、ESLint 与 production build；确认现有同步和 VOC 数据未被改写。
