## 2. 业务边界与审核决定

### A. 主流程恢复为原版

站点/类目/数量 → 查看可用缓存或开始采集 → 已到达来源展示业务报告 → 人工标注及纳入/移出 → 立即重新统计。

- 七区顺序保留：类目销量看板、TOP商品、上架年份、形态销量、形态价格带、品牌价格带、综合结论。
- 不要求预填形态目录，不以保存报告或Agent解释作为查看条件。
- 本地规则拥有数字与状态；不增加模型调用。
- 保留目前可直接输入形态的便利，补回原版候选形态及管理操作，不退回只能输入或只能下拉的单一操作。
- 研究结束月截断沿用当前已交付行为；近3/6月仍按最近返回点计算，2024/2025列和既有毛利分档保持。标题/说明交代覆盖情况，不在修复中重定义为连续自然月。
- 来源TOP100看板与当前纳入商品分析分别标注，不擅自换成同一分母。

### B. 缺失数据：推荐“展示已知合计，明确完整度”

这是本计划最需要审核的统计展示决定，批准前不修改：

| 情形 | 拟采用的展示与计算 |
|---|---|
| 本期间所有商品值均可计算 | 显示合计与原有占比 |
| 仅部分商品本期间值可计算 | 显示“已知合计”，附“可计算X/Y件”和缺失原因；不把缺失记为真实0 |
| 分母有缺失 | 可显示“已知销量内占比”，分子分母使用同期间、同筛选范围、同可计算集合；不得简称完整市场份额 |
| 形态内部份额 | 仅以该形态同期间的已知销量为分母，不以全商品池为分母 |
| 没有任何可计算数据 | 显示待采集、请求失败、来源未返回等具体原因，不显示0或0% |
| 来源明确返回0 | 保留0；已知分母为0时占比显示不可计算 |
| 已确认上架前年度 | 保留“不适用”，汇总贡献为0，不与上架后数据缺失混淆 |
| 返回月份不足 | 显示已返回月份/期间范围；“可计算商品数”不等同于完整自然月覆盖 |

示例：同一形态两件商品，A销量100，B无历史。显示“已知销量100，可计算1/2件”；A所在价格带占比可标“已知销量内100%”，不可解读为完整样本占比100%。一旦B返回100，自动变为完整合计200，A份额50%。

历史版本必须保留保存时规则版本和数据范围，不把旧报告静默改成新口径。新规则用新计算版本；旧版本保持原查看结果，新草稿使用新规则。

### C. 结论按实际数据依赖生成

- 移除“一项年度缺失就挡住多个分析区”的统一外层条件，改成逐条结论的数据依赖判断。
- 只依赖近6月的数据完整时，可以生成该项结论；与其无关的2024年缺失不得阻断。
- 真正依赖年度变化的结论仍需对应年度数据，不用0或缩小样本假装满足条件。
- 部分数据仍显示统计与明确缺口；不直接向原版评分函数塞入缺失补0的输入。
- 保留原版阈值、毛利分档及最低样本条件；只有全部必要证据满足时才生成综合评分/完整判断。
- “完整结论所需数据”和“允许展示部分统计”分别判定。

### D. 人工编辑自动保留，保存版本是可选操作

- 标注、纳入/排除在编辑后自动保存业务草稿。无需点击“保存当前版本”才能保留。
- 草稿隔离键包含当前账号、组织/项目权限范围、站点、规范类目节点；ASIN为商品对应键，不跨站点、类目或用户串用。
- 同一研究切数量、恢复任务、刷新页面保留当前商品仍在池内的编辑；缩容暂时移出的商品编辑保留，扩回时恢复。新ASIN默认纳入、未分类。
- 以数据库草稿为长期来源，网络保存失败时保留本地待同步草稿并提示；自动保存不调用供应商、不创建分析任务或历史报告版本。
- 并发修改使用草稿版本校验；发生冲突保留本地编辑和服务器草稿，不要求先覆盖本地内容才允许处理。
- 保存报告只生成可回看的快照；版本备注选填。快照注明当时来源覆盖及规则版本。
- 区分“恢复移出的商品”与“恢复某个报告版本为草稿”：前者只恢复纳入状态，后者备份现有草稿后恢复该版本，不暗中改备注/形态。

### E. 缓存与启动行为

- 查看已有任务、刷新状态、切换报告版本、改人工标注只读来源，不触发重新采集。
- 点击同条件筛选：有同权限范围内的进行中任务则进入该任务；有可用报告缓存则展示；没有才创建任务。对重复提交做服务端约束，不能只靠按钮禁用。
- 缓存条件包含权限范围、Sorftime来源版本、站点、规范节点、研究月份、目标数量及采集参数；不跨范围复用。
- 推荐沿用原版服务端报告缓存7天有效期，页面显示来源时间；3天客户端副本不作为强制重采条件。读取用户指定历史报告不受新查询缓存有效期影响。
- 明确“重新采集”才更新来源；失败数据不当作完整缓存，重试只针对原任务可重试的失败项。
- 采集中维持原版的启动入口与数量控件一致禁用，不顺手放开并发扩容。查看已有结果与可用的人工编辑不因采集进行而被禁止。
