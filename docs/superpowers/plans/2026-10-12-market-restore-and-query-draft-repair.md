## 三、用户操作规则与 UI

### 3.1 恢复另一任务

当前报告 A → 输入目标 B → 显示“正在读取目标任务，当前报告保留” → 成功后展示 B；读取失败则继续展示 A。

- UUID 格式错误：不发 GET，提示格式问题，不改当前报告。
- GET 进行中：不清空当前图表、历史版本及人工草稿，不提前改 shapeRun/themeRun；恢复目标按钮显示读取状态，提供取消读取。
- GET 失败：在恢复工具附近提示“目标任务读取失败，仍显示原任务”；没有旧报告时改为“未读取到任务”。不再声称页面上不存在的结果被保留。
- GET 成功：仅最新有效请求能提交切换；切换报告、报告版本、已显示任务 ID 和当前模块 URL，然后按条件回填规则处理查询输入。保留其他模块 URL 参数。
- 取消读取、切换模块、卸载组件：中止目标请求，使其回包失效；即使底层请求无法及时取消，也不能应用旧结果。
- 恢复同一已展示任务：只刷新其状态，保留历史版本选择、查询草稿和未保存人工编辑。
- 人工修订保存中：不允许切换任务或发起目标读取；避免把 A 的保存结果套到 B。
- 存在未保存的形态分类、选择、价格带或备注：可以先读取目标；成功切换前在页面内确认是否放弃这些修改。取消则保留全部原状态。确认之前还需重新检查保存状态和请求是否仍有效。
- 如果等待目标 GET 或确认期间出现新的人工编辑，重新检查脏状态，不能沿用旧的放弃修改判断。
- 查询条件草稿与人工修订草稿分开处理：仅查询条件更新不触发“放弃人工修订”确认，而由输入修订保护决定是否回填。

### 3.2 查询条件回填

| 操作 | 回填规则 |
| --- | --- |
| 显式恢复不同的有效任务，等待期间没改输入 | 回填目标报告的站点、类目、月份及已有样本参数 |
| 显式恢复期间修改输入 | 报告可切换，但保留最新输入，显示“查询条件与下方报告不同” |
| 打开 task 深链接且类目为空 | URL 完成初始加载后回填保存范围一次；等待期间有编辑则保留编辑 |
| 完整非空查询草稿 + 已保存 task 地址 | 初次读取、刷新页面和导航返回均保留草稿 |
| 普通状态刷新或轮询 | 只更新任务状态/报告，不改查询条件 |
| 更早任务响应在后一个恢复之后返回 | 不回填、不切换报告，也不消费后一个请求的回填意图 |

“缺条件”明确沿用 F-01 的空类目判据，不把非空但无法解析的用户输入当成自动恢复授权。评论的输入修订要覆盖站点、类目、起止月份、主题样本数量及商品池数量；完整刷新持久化以现有模块 URL 能表达的查询范围为准，本次不另建本地缓存保存系统。

### 3.3 失败分类与权限

- 目标 404：停止自动读取，不创建任务、不自动重新采集；可改目标 UUID 后再读。
- 目标 403：不展示目标数据；保留当前会话仍有权访问的原报告，明确目标无权读取。
- 会话失效 401 或当前报告权限被撤销：遵从现有登录/权限清理流程，不能用保留旧画面绕过权限。
- 目标网络错误或 5xx：本次目标请求结束，原报告保持，提供手动重读，不加入无限重试。
- 当前任务普通轮询：保留原有网络/5xx 有界退避；对明确 404 停止自动重试，保留缺口提示及允许的旧显示。
- 取消读取属于前端 GET 取消，不是取消后台采集任务；按钮命名不得混淆。
