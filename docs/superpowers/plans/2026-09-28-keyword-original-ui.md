# 模块三原版 UI 收拢 Implementation Plan

> 执行方式：按已确认方案使用 executing-plans，独立文件可并行实现，整合后统一验收。

**Goal:** 主页面恢复原版业务顺序，新增管理功能通过独立按钮展开，技术核对仅管理员入口显示。
**Architecture:** 使用已有 showAuditDetails（由登录角色派生）传给模块三；查询、业务报告和分类标准为主视图。人工工作区常驻但默认隐藏，按钮展开独立面板，保留草稿/保存/版本/切换确认。任务面板默认隐藏，状态与失败重试就近显示。管理员单独展开技术核对面板。
**Tech Stack:** React/TypeScript，现有 CSS、Playwright、Node test；不改数据库、API、统计公式。

用户已在上一轮同意界面方案并明确要求修复；继承此前测试后直接发布的授权，不再重复征求同意。

- [x] 新增浏览器失败用例：主页面不显示人工版本空卡片、原生多选编辑器及技术明细；成员没有管理员核对入口；管理员可展开核对。
- [x] 调整报告层：来源追溯/严格核对移入管理员独立区域，普通业务缺失说明保留；来源明细表入口与审计区域分离；新增评分/建议折叠为可选业务明细，计算保持不变。
- [x] 调整工作区：人工编辑/历史报告按钮入口，关闭时保留未保存草稿，无人工版本不占空卡片；紧凑任务状态、失败重试与任务管理入口。
- [x] 浏览器验证原版主顺序、面板开合/草稿保留/保存恢复、状态失败/重试、管理员与成员；检查桌面截图。类型检查和相关回归通过。
- [x] 检查正式基线、保留回滚点、受控发布，正式角色和实际入口验收；不重采来源、不修改用户人工报告。

不新增业务规则，不撤销现有人工历史数据；手机版和模块联动继续延后。管理员可见为前端展示边界，现有组织鉴权不变，不声称新增服务端字段保密权限。
