# 区域四：已保存商品详情毛利补齐

使用 executing-plans 按下列任务逐项实现；沿用用户已批准的外部数据缺口修复范围。

**目标：** 修复商品详情已有毛利率、扩展商品仍显示未知的问题，不改变原版计算公式。

**设计：** 商品池与图片采集快照保持原样。读取已验证的同任务 product_detail 时附加可选毛利观测（原字段 gross_profit_rate、详情售价）；当前草稿适配器只在原值为空、ASIN精确一致、两处售价一致且大于0时补入。图片缺失不影响有证据的毛利。失败、缺字段、价格不同不补。旧版本内未存此观测继续保持旧结果。

**排除：** 不按FBA费自行估算毛利，不替换变体，不修改售价，不为日期1970/Unknown或历史缺月补零，不发起全量重采，不改变缓存7天规则，不重写来源/输入/报告历史。

**事实：** 落地灯140件的40件扩展商品缺毛利；商品搜索响应无该字段，已保存商品详情有 gross_profit_rate（来源doc明确percentage value）。原版扩展搜索也未补此字段。部分详情售价与商品池不同，需保留缺口。

- [x] 1. 补失败测试：读取已保存详情、身份校验、零值/非法值、空图片、价格冲突、原值优先、旧记录兼容。
- [x] 2. 合约增加可选观测；读取器在现有快照重放验证后提取；适配器保守补齐；现有毛利单元格和缺失折叠说明来源与缺口。
- [x] 3. 原版规则、冻结修订、实际样本只读校验；核实年度缺口和D1—D5，不将供应商缺口报作已完成。
- [ ] 4. 类型检查、构建、发布、真实入口和截图验收；保存回滚引用与证据。

验收：同输入原版公式不变；来源快照与历史哈希不变；页面读取不调用供应商；可补部分明确计数，价差和外部缺失分别说明。
