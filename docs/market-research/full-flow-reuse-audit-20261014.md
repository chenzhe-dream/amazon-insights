## 测试口径与边界

- US 虚拟类目 12:34，研究区间 2026-07 至 2026-09；默认四模块联动的形态商品池为 100，再通过真实 startShapes 接口扩容至 150。没有将 UI 默认值改成 150。
- 买家评论取 TOP20 Customers Say；竞品取前 10 个 ASIN，全部与市场池重叠。关键词固定返回 2 个有效词，扩展商品每页最多 20 个，竞品每个仅一个变体；这不代表真实类目的关键词数、变体数或分页数。
- 总览分布为简化合成桶，利润补充对应一个 ASIN；不能把本次数量作为真实 150 商品场景固定收费上限。
- Sorftime 通过 loopback HTTP JSON-RPC 与生产公共客户端，使用真实 PostgreSQL 缓存；市场 SellerSprite/SIF 通过注入的虚拟 connector，竞品 SIF 通过 loopback HTTP。统计的是业务取数请求，不包含握手、探活等协议请求，也不是供应商扣费凭证。
- 竞品走 Sorftime 底库分支，依次执行底库、SIF 关键词、评分、评论、趋势、变体、子体销量、价格策略、FBA、图库、类目趋势和 SIF 流量脚本并写入隔离文件。未把测试报告发布到前端。
- 四模块综合场景使用规则路径，未启用付费语义模型。另跑总览模型报告恢复、翻译缓存、联动 HTTP 回归，模型响应完全合成。图片 AI、Alexa 人工录入、SellerSprite 主底库/西柚分支、完整 sync-job 状态发布及浏览器点击没有包含在同一次计数中。

## 已证实的复用与剩余机会

### P0：把共享源缓存扩展到 SellerSprite 与 SIF

本轮仍有两组完全相同的首次请求：

1. SellerSprite `market_research`：基础入口和详细总览各一次，站点、类目、月份、newProduct、topNum、page、size 完全一致。
2. SIF `market_get_keyword_history`：市场关键词和竞品关键词各一次，站点、月粒度和两个关键词完全一致。

同一批次下即可少 2 次；有效期内重新新建相同市场批次，本轮观测的 47 次均可列为共享缓存候选。后者是优化目标，尚未实现或验证为 0。鉴权、站点、完整参数、凭据、TTL、原采集时间、显式刷新及失败暂停都必须保留。

`market_research_statistics` 虽然名字相同，基础入口 topN=10、详细总览 topN=100，不能直接视为完全重复。不同供应商提供相似关键词/趋势也不能直接合并成同一来源。

### P1：商品详情从逐个必采改为缺字段补采

本次市场商品池已包含有效主图和毛利率，形态仍执行 150 次 `product_detail`。详情证据还参与毛利率读取，不能仅看任务名“图片”就删除。

建议先定义字段完整性规则：图片、毛利率、ASIN/站点、来源时间与口径均足够时复用已冻结商品池；缺字段或主动刷新再补详情。详情用于竞品的评分、FBA、完整图库等字段仍保留需求判断。若本轮 150 条市场详情都满足可省条件、10 个竞品仍需详情，净节省上限约 140 次；只是有条件的上限，尚未实现。

不得把主图当成完整副图图库；同样不能把类目销量当成单品销量，或把 SalesVolume 与 SalesAmount 合并为一个已验证接口。

### P1：SIF 批量结果按词拆分复用

当前 ASIN 关键词脚本已先合并相同词再批量采集，10 个竞品共享两个词只产生 1 次历史和 1 次推广评估，避免了每 ASIN 重复请求。下一步可将成功响应按“凭据＋站点＋词＋粒度/范围”持久化，并只对缺失词组批；不能仅按整个数组缓存，否则相同词因组批顺序变化仍可能重采。

### P1：统一新鲜度并保留补抓边界

竞品已有文件缓存可让重复执行为 0；但 `REFRESH_STALE_DAYS` 默认 0 表示无自动过期，不能据此声称每次分析都是最新数据。共享原始缓存的 TTL 和报告/生成文件缓存需要统一到明确的“读取历史 / 更新数据 / 补抓失败项”语义。

### P2：减少重复后台计算

扩容或新建报告即使命中原始缓存，仍需创建、执行和落库数百个来源步骤。后续可研究复用解析结果、批量落库与同一报告的恢复入口，但必须保持新报告的范围和证据绑定。节省这部分改善等待时间，不应计为省下的 MCP 额度。

翻译已有固定词条与持久化内容缓存，重复文本可跨报告复用；本轮独立测试覆盖失败项单独重试、目标语言隔离和重启恢复。不同站点仍需对应站点的数据，翻译不能替代采集。
