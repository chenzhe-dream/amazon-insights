# Sorftime 共享取数：候选验证记录

日期：2026-10-14。范围：市场调研按 150 商品、竞品概览按 10 ASIN 验证跨模块复用。已实现并启用 32900，未发布 31900、未归档、未消耗真实 MCP 额度。

## 改动

- 市场 connector 和竞品采集脚本进入同一个 Sorftime 原始响应缓存，使用 PostgreSQL 持久化。进程重启后仍可命中。
- key 包含供应商 endpoint、凭据散列、工具名及完整请求参数；同凭据、同站点、同商品、同指标、同分页与筛选条件才复用，不使用 jobId 隔离公共来源。各报告仍保留独立结果。
- 跨进程 advisory lock 合并同时发出的相同请求；只有缓存未命中才进入供应商物理调用治理。
- 100→150 扩展只补缺失请求。竞品 10 ASIN 若已被市场商品池覆盖，可复用对应详情、趋势、内容或评论接口响应；未采集过的字段仍需请求。
- 缓存保留来源采集时间，读取不会把旧数据标成今天新采集。
- 明确的额度耗尽暂停同凭据未命中请求 1 小时，允许读取有效缓存；网络失败不进入成功缓存，并作短暂退避。
- 支持显式强制刷新；形态重新采集任务记录刷新起点，任务内后续步骤可复用该起点后已经取回的数据。
- 增加缓存命中、物理 dispatch、失败、额度阻断事件及请求清单预算。估算单位不是供应商账单，未知接口费率保持未知。

TTL：详情/变体 6 小时；内容/图库 7 天；趋势、类目、商品池、关键词、评论等支持接口 24 小时；已识别的空数组结果 5 分钟。过期数据不会作为新鲜缓存返回。默认关闭，候选服务设置 SORFTIME_SOURCE_CACHE_ENABLED=1；启用时缓存不可用则明确失败，不静默绕过缓存付费。

## 固定清单的节省量

离线固定请求清单：635 次逻辑请求合并为 530 次物理请求，估算由 2148 单位降至 1873 单位（减少 275，约 12.8%）；有效期内重复相同清单为 0 次新增物理请求。

这是测试清单，不是完整四模块真实账单：不含 SellerSprite、SIF、大模型、额外变体分页或清单外接口。首轮 150 商品的销量与销售额两类趋势仍有 300 次独立物理请求，不能靠缓存免除首次必要取数。缓存不会自动迁入所有历史任务的原始响应，新缓存首次启用为空。

## 运维与剩余验收

在加载目标运行环境后使用以下命令；不输出或传递明文凭据。这些命令不会调用 Sorftime：

```powershell
node scripts/sorftime-source-cache-admin.mjs summary
node scripts/sorftime-source-cache-admin.mjs estimate requests.json
node scripts/sorftime-source-cache-admin.mjs resume
node scripts/sorftime-source-cache-admin.mjs prune
```

requests.json 为 [{"tool":"product_detail","args":{...}}] 数组，应使用真实入口的完整参数生成。summary 统计最近 24 小时；resume 在确认补足额度后解除对应凭据暂停，但不启动采集；prune 清理过期超过 30 天的源缓存和超过 90 天的事件等旧记录，需按维护需要主动执行，未新增自动任务。

待用户验收 32900：四模块导航、历史报告读取、竞品页面读取正常。当前额度不足时无需点击真实重新采集；本轮取数逻辑以离线虚拟供应商测试为证据。额度恢复后的真实缓存命中与账单对照另行核验。用户验收通过后才允许推进 31900 发布及发布后复核。
